# 独属记忆、定向共享与修正

状态：用户已接受的首版体验默认，2026-10-25；未实现或体验验证。依据 [PRD](prd.md)，沿用已接受的 [状态与节奏](state-and-rhythm.md)。不增加记忆商城、角色照料或逐条审批任务。

## 每位Bayper记住什么

| 内容 | 默认归属与使用 |
| --- | --- |
| 用户直接告诉这位Bayper的事情 | 归这位角色；重要且明确的偏好可长期保留，临时话题不自动永久化 |
| 用户与这位角色真正共同经历的事情 | 按实际参与者归属，是她的独属共同经历 |
| 角色自己的日常与探索 | 归执行者；区分实际进行了什么与主题故事中的虚构表达 |
| 经授权的Coding Agent会话分析 | 归实际获准了解该来源的角色，保留外部来源与推测性质，不当作用户亲口确认 |
| 另一位Bayper分享的事情 | 接收者记作“听谁说过”，保留来源，不记成自己的亲历 |

角色只读取自己持有的有效记忆和明确分享给自己的内容，不因为同在小窝、换上同一套服装或使用同一个模型就知道别人全部聊天。新角色不会自动获得其他人的历史，也不能凭用户昵称猜出旧经历。

重要偏好与共同经历长期保留；普通琐碎细节可降低提及频率、归纳或淡忘，未使用一段时间不删除重要经历。用户明确要求记住的内容优先；“这次临时这样”不改写长期偏好。亲密度与记忆有效性分别判断，不靠刷亲密才记得重要纠正。

自动记忆整理沿用现有调用预算，优先随已有交互/活动整理，不每条聊天另发一次提炼、评审、共享请求。数值计算、明确操作的本地生效不依赖所有角色轮流调用API。

## 来源停用与授权撤销（Codex补充建议）

关闭分析或撤销目录授权后，停止对应来源的新读取和分析，不继续发布尚未生效的在途分析结果；不影响用户直接聊天或Herdr事实通知。既有合法形成的记忆保留来源标识，默认不自动删除，也不自动传播；用户可另行删除该来源形成的记忆，沿用关联失效与防回流规则。重新授权不解除已有删除限制。首版自动分析只归属于有资格的名单角色并占已有预算，不另设全局模型后台。具体授权说明必须区分停止分析与清除已有记忆。

## 默认不全员共享

共享是**一个讲述者向一个接收者讲一小段事**，不是打开全员共用记忆库。

| 内容 | 自动共享默认 |
| --- | --- |
| 已提供主题中的轻量日常、探索见闻，以及角色之间有关联的小故事 | 可以少量定向分享；只含必要片段，不附带完整对话 |
| 用户私聊形成的偏好、个人信息、心事或用户明确“只告诉你”的事 | 不自动分享；用户指定可告诉谁时才转告 |
| Coding Agent会话原文、工作细节、外部分析推测 | 不自动在角色间转发；来源授权不等于共享授权 |
| 用户明确要求“告诉B”的内容 | 只分享指定内容给B，不顺便广播或带上其他记忆 |
| 尚未核实、被纠正、已删除或明确禁止分享的内容 | 不分享，也不能靠改写措辞绕过 |

自动共享由合资格名单成员发起，接收者默认也从当日名单中选一位有关联的已结识Bayper；没有自然对象就不分享。建议**全应用滚动24小时最多1次自动共享**，是上限而非任务，消耗既有自动活动/API预算；用户明确转告不参与随机抽取，仍遵守调用设置。

接收事实可以在本地记入，不要求接收者立即模型回应。用户明确指定名单外角色时可投递，但不因此授予她自动API资格、切到桌面或改名单。自动分享不二次转发；用户另外明确转告时继续保留原讲述来源。

默认不为共享逐条弹确认框：可自然分享的范围很窄，其他内容保持独属。用户可说“这件事不要告诉别人”“以后不要自动互相讲我的事”；限制持续生效，不要求每天重设。共享结果可在相关角色记忆里简单查看“谁告诉了谁”，不生成待办通知。

## 纠正与删除的简单范围

默认处理的是**这件事的相关理解**，不复制给所有角色，也不清空整个人格。

| 用户表达 | 默认动作 |
| --- | --- |
| “你记错了，我其实更喜欢茶” | 修正这一偏好；已有同一错误理解和相关共享派生内容的角色同步更新或失效 |
| “我最近只想喝茶” | 作为有时效的当前情况，不直接永久推翻历史长期偏好 |
| “忘记这件事”／删除这一条记忆 | 默认从当前角色及其他已经持有同一项/相关派生项的角色中清除其可用记忆 |
| “只让A忘记这件事” | 只清除A持有的相关记忆并阻止自动回流给A，其他已知者保持；不通过A再新增共享 |
| “以后别再分享这件事” | 停止后续共享；若之前已分享，如实简短说明，不假装从未发生 |
| “这件事只让你记得” | 保留当前角色独属，清除其他已有持有者的对应可用理解并阻止再次传播，不用逐角色下令 |
| “帮我告诉B这件事” | 定向分享指定片段；不把整段聊天或其他偏好一起发出 |

如果“这件事”可以从当前对话或选中记忆定位，就直接处理并简短回应一次；无法定位时只追问最小范围，不猜着删除整段历史。无需用户在各角色间重复下令。默认范围有清楚的一句话说明，用户可明确缩小。

“同步纠正”只触达已经持有同一理解、直接副本或相关派生信息的角色；不知道这件事的人不会因此被告知。用户对同一明确事实在其他角色处独立说过，也需要核对这次纠正是否适用，不能只改一条记录ID就宣称所有错误已清。

不同角色对同一经历的感受可以不同，不必统一为一句话；用户明确纠正的事实与当前偏好应一致。修正偏好不抹掉真正发生过的经历：可以保留“以前一起喝过咖啡”，但不能继续断言“你现在最喜欢咖啡”。

## 怎样同步生效

1. **先停用旧理解，再确认完成。** 识别范围后，本地首先限制旧内容继续检索、影响行为或被分享；需要模型重新整理的内容可以随后处理。无法定位/保存时如实说明，不先答应已经全部完成。
2. **关联副本与派生内容一起处理。** 摘要、共享转述、由其产生的偏好标签与习惯依据、待发送分享都要更新或失效，不只改角色的可见记忆列表。无关记忆和已确认内容进度保持。
3. **角色没上场也立即失效。** 无需把每位角色叫醒或用API逐个通知；她下次检索、生成、活动或共享时只能使用有效内容。修改不依赖她在当日名单中。
4. **处理在途和缓存。** 已装入对话上下文、待显示气泡或生成中的任务也检查有效版本；依赖旧理解的结果不继续发布或保存，必要时仅做一次简短修正。明确选中或已定位的记忆可本地删除/停用，不因模型服务不可用而等待；尚未定位时不冒称已处理。
5. **阻止自动重新学回。** 旧聊天、外部会话重新分析、缓存或历史共享不能恢复用户已纠正/删除的同一理解。只保留执行该控制所需的最小信息，不把被删正文藏进一份可继续聊天的“审计记忆”。
6. **允许用户之后明确改变决定。** 用户重新说明“现在可以记住这件事”或主动给出新的当前偏好时，可建立新的有效理解；旧文件重复导入不算用户重新同意。

纠正、删除、限制共享都不扣亲密度、精力或心情，角色不抱怨用户让她忘记，也不要求重新培养关系才能生效。系统只向用户确认一次，不让多个角色轮番弹出“我也改好了”。

## 删除的内容边界

“删除记忆”清除Bayper可使用的对应记忆正文及相关派生理解，并保留必要的最小防回流控制。它不自动删除用户的原聊天历史、外部会话文件或已发送到服务商的请求；这些来源不是记忆本体，后续不能再被当作恢复该记忆的依据。没有技术验证前不承诺跨服务商撤回或物理存储介质上的不可恢复擦除。

删掉一段共同故事不会自动取消角色结识、服装解锁、现有亲密数值或连接器通知记录；若用户要清理这些事实，应按其对象明确处理。若故事中含已删除的个人信息，内容进度可以保留完成标记，但展示时不再带回该信息。

删除后已在屏幕出现或用户已经读过的文字不声称从未发生；界面可清理当前可控展示，之后不继续使用。具体操作入口、原文删除和全量重置另行设计，本轮不扩展一整套管理后台。

## 自然使用示例（纸面推演，非实测）

- 用户只与A聊过一个偏好：B不会因为同在小窝自动知道；A也不自动向全员讲。
- A把主题探索的小故事告诉B：B可以提“听A说”，不宣称和用户一起亲历；不再自动传给C。
- 用户纠正A的错误偏好，B此前收到过：A与B的相关理解一起更新，C不知道该事就没有新记忆或弹窗。
- 用户删除一条后来被共享的记忆：相关共享摘要和待发表内容失效，关着应用的角色下次回来也不能复述旧内容。
- 用户只让A忘记：B已有相关内容可以保留，但系统不能在下次共享/分析时又自动交回A。
- 用户一周没打开：重要记忆、分享限制与删除控制仍有效，无照料和逐条确认欠账。

本轮只定义业务归属与同步要求，不实现记忆判定、共享、数据库结构、检索索引或删除管线。既有SQLite构造实验只验证局部存储，不能当作这些语义已经通过。
