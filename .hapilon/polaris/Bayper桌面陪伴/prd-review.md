# PRD跨系统复查

日期：2026-10-25。依据 [主PRD](prd.md) 及其陪伴、状态节奏、线索、记忆细化文件。本轮仅纸面复查，不代表代码、素材或体验验收通过。记忆与共享默认已获用户接受；本轮新增边界建议由Codex提出，不冒记为用户逐项确认。

## 整体判断

产品概念主链具备闭环：模型配置→愿望首遇→接纳进入小窝→名单/单一同屏陪伴→互动与独属记忆→低频活动/故事→后续相遇或服装解锁→继续陪伴。连接器事实通知独立于这条陪伴链；没有模型、角色休息或探索时仍需通知。

不必增加新的业务系统。尚不能称为可直接开发验收的完整规格：通知已明确普通3位之外另设加急位置；模型接入、记忆语义和正式动画仍需实现验证。

## 发现与整理结果

| 问题及影响 | 处理与所在依据 |
| --- | --- |
| 模型关系表只说同屏来自名单，与名单外临时聊天冲突 | 已统一为自动来自名单、显式临时聊天例外；不改变名单或自动资格，见主PRD |
| 探索者不能同屏，但启动探索后的交接、主动找她聊天尚未收口 | 用户明确探索就退出桌面并换人。已归入陪伴规则；Codex补充建议无人接替不派当前者探索，主动聊天可暂停探索，短节点后交接 |
| 长探索跨名单刷新、关闭/恢复后，可能偷偷继续工作或重复计费 | 补充暂停保存、离线不推进、恢复重新核对资格；同次活动不重扣精力/启动额度，新增API仍计预算，见陪伴规则 |
| “安静陪伴不耗”与－6/小时冲突；模型预算耗尽可能错误阻断纯本地动作/故事 | 统一为陪伴轻耗，微表情不额外扣；API预算仅限制模型请求，本地活动仍受原活动资格与上限约束，见状态与节奏 |
| 撤销会话目录授权后是否清空记忆、分析能否继续不明确 | 建议立即停止新读取与在途分析结果生效；已有记忆保留，用户可另行删除；重新授权不恢复已删理解，见记忆规则 |
| “不抢焦点”与用户主动文字输入、模型不可用后的本地陪伴缺边界 | 自动行为不激活；显式打开聊天允许输入焦点。完成首次配置后API故障保留本地陪伴与事实通知，输入窗口与故障体验仍需验证 |
| 多服装与更多动作可能换脸、穿帮或缺片段后偷偷换回基础衣服 | 新增动画规划：核心身份基准、服装参考、动作覆盖与实际播放验收；当前没有正式母版，不能宣称问题已解决 |
| 普通气泡满额可能延误紧急事件 | 用户明确3个普通气泡之外另设加急位置；P0独立表达，不挤占普通位置，具名分组与时效仍需实测 |

以上边界建议已归到各自规则文件；本页只记录复查依据与缺口，不另维护第二套数值表。

## 通知的产品决定

用户已明确：3个普通气泡位置照常设计，之外单独预留加急气泡位置。P0不等待普通队列，不覆盖现有气泡。多个P0的具名分组、最短阅读时间和展开明细以主PRD为准，属于既有通知系统的呈现规则，无需增加业务概念。

本轮用户要求暂不讨论首版范围和落地验证安排，只进行技术子系统职责划分。以下保留既有研究边界，不作为本轮待决议题。

## 留给后续切片验证的内容

- 首次API配置的可用性验证、失败修复和后续模型故障体验；不因只填了Key就虚称联网成功。
- 连接器稳定身份、观察缺口、事件去重与通知队列在产品中的真实联动，不能复用探针PASS冒充产品通过。
- 记忆判定、语义纠错、关联删除、防回流及调用成本；SQLite检索通过仅为局部证据。
- 角色/服装的基准图、动画覆盖、输入焦点和跨Spaces实际交互。当前没有正式角色成品。

这些是现有需求的落地风险，不需要另加收集、养成或调度概念。本轮不进入正式开发或冻结首版范围。
