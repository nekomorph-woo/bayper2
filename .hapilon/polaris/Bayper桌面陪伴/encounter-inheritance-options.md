# 新流浪者发现、入住与记忆传承：三版候选

日期：2026-10-25。状态：三版比较历史，未实现。用户已选择“A为基础＋B的居所线索连续性＋C的同伴引荐”，现行规则以 [组合方案](encounter-inheritance-rules.md)为准。依据：[PRD](prd.md)与[造型元数据库](../../../tools/appearance-catalog/README.md)。本文件保留当时的比较，不作为三套并行有效规则。

## 三版共同遵守的既有规则

- 初始1只，最多3个在住名额；临时出门占名额，永久离开才释放；新入住用户确认，可拒绝。
- 满员默认只出现居所线索，不发现或预创建新的等待入住个体，不用屏外候选绕过上限。
- 只有随版本提供、通过素材验收的角色才能实际相遇与入住。数据库的文字候选、概念图、未完成动作不算可用角色。当前没有已发布角色。
- 不在运行时生成图片；角色造型引用制作好的配方/素材版本。主题是上层组织，不等于身份或性格。
- 用户和全部个体都是流浪者，只有友情与亲情。新入住不是后代、重生或人格复制。
- 探索不扩大来源权限，外部会话分析仍默认关闭且须明确目录授权；没有外部源也能围绕已有互动与记忆活动。
- 连接器与 Agent 状态独立；出入、发现和传承不能阻塞必需通知，无宠物在场时应用继续通知。

## 共用的数据归属建议

| 信息 | 建议归属 | 不应混淆 |
| --- | --- | --- |
| 眼形、身材、服饰、配色等参数 | 造型维度与配方 | 不是真实用户偏好或宠物经历 |
| 已制作图片和方向动作覆盖 | 素材版本 | 有描述不等于有素材 |
| 哪些角色可被遇到 | 已发布角色集合 | 不是所有候选要素的自由笛卡尔积 |
| 居所线索与选择题回答 | 用户相遇进度与暂定倾向 | 不自动等于已发现具体个体或永久偏好 |
| 个体身份、性格与关系 | 运行个体 | 相同图片不等于相同身份；复用规则待定 |
| 用户明确纠正的重要偏好 | 可修正的有效理解 | 不因传承旧副本而复活错误理解 |
| 旧个体留下的故事 | 有来源的传承内容 | 新个体获知故事不等于亲历故事 |

以下都是概念归属，不是本轮新增生产数据库表。造型库只保存外观资料；未来的个体/记忆/进度应按职责组织，不能因为都可用 SQLite 就塞进同一张属性表。

## A版：轻量相遇与行囊传承

**核心体验：偶遇新朋友，离开时留下一份简洁的行囊。**

发现：探索或日常活动偶尔带回居所线索。满员只保留地点氛围、物品或生活习惯等叙事信息；有空位后，从已发布角色中挑选符合线索且有辨识度的形象，再形成具体相遇。选择题给出粗粒度倾向，不展示捏人参数，也不自动认定用户终身喜欢某种外貌。

入住：一次只认真认识一个新朋友，用户可以接纳、暂缓或拒绝。接纳时再次核对空位；无空位则不入住，也不挤走旧个体。拒绝不惩罚、不立即换一个重复询问。拒绝冷却与是否能再次相遇待体验细化。

传承：旧个体可以整理一份“行囊”，包含少量重要偏好和几段共同故事。建议用户预览并决定保留/不传；新个体接收后仍有独立底色，提及历史时说明“听前辈说”。不复制原聊天原文、临时情绪或全部记忆。

数据需要：已发布角色引用、少量线索/倾向、相遇决定、独立个体、传承内容及来源。额外进度最少；无需先建立复杂世界或任务树。

优点：克制、容易理解，快速形成完整陪伴闭环。代价：相遇过程与长期世界连续性较弱；选择题不能承诺精确指定下一只造型。

## B版：居所档案与渐进结识

**核心体验：先慢慢了解某处生活，再认识住在那里的人。**

发现：探索积累居所信息，线索有稳定的叙事归属与进度。满员时只认识“地方与生活痕迹”，不生成具体新个体身份；空位出现后，才把完整线索与一个已发布角色关联，开启正式结识。未知未来主题不承诺一定有对应角色。

入住：通过几次短互动了解对方的习惯和性格，然后由用户邀请或拒绝，不要求刷好感。形象来自已制作角色，个性在认识过程中显露；用户不需要填完310个参数才能相遇。相同线索再次出现时延续进度，不每次随机换一个背景。

传承：旧个体可以留下多份有标题的故事或书信，新个体随着相关话题逐步读到。建议用户能查看并排除某些内容；永久离开与故事接收不必捆绑同一刻。重要纠正应优先于旧信内容，不借“它还没读到新信”继续输出已明确纠正的误解。

数据需要：居所线索归属、阶段进度、空位后的角色关联、结识记录、分组传承内容和阅读状态。比A更多持久叙事状态。

优点：相遇更有铺垫，探索与长期陪伴联系更强。代价：容易膨胀为收集/养成任务，需要防止重复线索、等待空位焦虑和“为了见新人逼旧人离开”的暗示。

## C版：同伴引荐与关系接续

**核心体验：通过已有同伴的故事，结识另一位流浪者。**

发现：在住或已离开的同伴带回居所线索。满员时只谈地方、旅行与生活见闻，不生成具体候选；有空位后，才从已发布角色集合中形成一位被引荐者。外观与关系没有血缘约束，不能按旧个体的脸复制“继任后代”。

入住：新朋友先与用户及在住同伴有一次短暂交流，用户决定是否邀请；同伴可以表达意见，但没有否决用户接纳或强迫其接纳的权力。素材更新增加可遇角色，不改变已有个体身份和历史。引荐者不必永久离开，避免把找新朋友等同于替换旧朋友。

传承：由引荐或离开的个体提供与新朋友有关的少量记忆，再由用户决定接受范围。继任者逐渐加入关系网，记得“谁告诉我什么”，不继承旧个体对用户的全部亲密程度。新个体可以形成自己的看法；用户纠正和删除现行记忆的要求不能被旧关系覆盖。

数据需要：个体间关系、引荐来源、故事来源链、传承接收范围、多个叙事主体的连续性。比A/B更依赖多角色一致表达。

优点：最能体现 Bayper 彼此的陪伴，离开与新入住更自然。代价：复杂度最高，容易把引荐暗示成已存在但未计数的额外个体；必须坚持满员时只有居所信息、空位后才创建相遇身份。

## 传承共同需要解决的规则

无论哪版，建议先保证以下语义，再选存储实现：

1. 传承记录谁整理、从何获知、接收者是谁；真实原始会话不是记忆载体的要求保持。
2. 接收前确认重要偏好的有效版本；传承只引用/整理仍有效内容，明确纠正后的旧事实不得复活。派生故事也应能追溯受影响来源。
3. 删除或纠正原记忆时，对已传承内容标记失效或重新整理；具体传播时机与用户控制入口待设计，不能许诺已实现自动传播。
4. 故事可有情感表达，但不能伪造亲历；不继承短期情绪、拒绝通知的倾向、旧个体全部亲密关系或外部数据源读取权限。
5. 不为了获得下一只而鼓励永久离开；建议永久离开须用户明确确认，拒绝入住、取消离开与跳过传承不受惩罚。永久离开是否保留联系、能否再次相遇仍是共同未决问题。
6. 旧角色素材被更新、停用或回滚时，已经入住的个体身份与记忆不能跟着丢失；正式版本保留策略需后续切片核实。

## 对比与建议

| 维度 | A 轻量相遇 | B 居所档案 | C 同伴引荐 |
| --- | --- | --- | --- |
| 最突出的价值 | 日常自然、负担低 | 探索有连续感 | 多角色关系有生命感 |
| 额外持久数据 | 较少 | 中等 | 较多 |
| 对未完成素材的依赖 | 不允许 | 不允许 | 不允许 |
| 传承组织 | 简短行囊 | 渐进书信 | 带引荐来源的故事 |
| 主要体验风险 | 相遇略浅 | 收集与等待负担 | 多主体关系叙事失真 |

比较时 Codex 建议先以A为基础、保留B的线索连续性并加入C的引荐。用户随后已明确选择此组合，详见现行组合方案；具体频率、概率、次数与交接体验仍需细化，不因组合获选就声称完整规则已经体验验收。
