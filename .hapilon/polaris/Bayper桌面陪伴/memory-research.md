# Bayper 记忆存储技术研究

日期：2026-10-25。用户要求调研业内方式，并提出 SQLite FTS5 + BM25。本文是基于官方文档与维护者资料的技术研究，支持正在讨论的 [PRD](prd.md)，不冻结工程选型。本轮未安装依赖、编写或执行探针，也未读取真实用户会话；没有中文召回率、延迟、容量或成本实测。

## 研究判断

优先把 **SQLite 持久化记忆 + FTS5/BM25 关键词检索**作为本地基线候选；用后续中文与同义表达样本决定是否加语义向量，组合成混合检索。暂不为个人桌宠直接引入完整记忆平台或时序知识图谱。

这是依据 Bayper 个人 macOS 自用、可纠正、可遗忘、重要记忆长期保留等要求作出的工程判断，不是性能排名。研究了 Letta、Mem0 与 Graphiti 的代表性方案，不是市场份额调查，不能称某一种已被证明为全行业主流。

## 代表性做法：通常是组合，不是单选数据库

| 代表方案 | 官方资料中的做法 | 可借鉴的原则 |
| --- | --- | --- |
| Letta | 区分始终处于上下文的 core memory、按需语义检索的 archival memory，以及可搜索的 conversation history | 角色身份、常用偏好与大量历史分层；原始会话不等于提炼记忆 |
| Mem0 Platform 当前 Graph Memory | 从记忆提取实体形成关联，检索结合向量、关键词 BM25 与图关联信号 | 关键词与语义可组合；实体关系是额外能力，不是存储一切内容的唯一方式 |
| Graphiti | 通过带时间的图表达实体、事实与经历，混合关键词、语义和图检索，保留事实失效的时间历史 | 偏好变化需要时间与修订语义；复杂关系查询才可能体现图结构价值 |

来源：[Letta 官方维护的 memory architecture](https://github.com/letta-ai/skills/blob/main/letta/agent-development/references/memory-architecture.md)、[Mem0 Platform Graph Memory](https://docs.mem0.ai/platform/features/graph-memory)、[Graphiti 官方仓库](https://github.com/getzep/graphiti)。以上为作者描述，不代表本机复现或独立验证其基准成绩。Mem0 的原 open-source 页面当前跳转到 Platform 文档，不将该页能力直接归为某个 OSS 版本；平台、开源库与数据库也不是同一层的选型。

归纳：来源进入后，需要判断哪些值得记、如何修正，再持久化并按情境取回；存储、检索、记忆维护和角色行为各有职责。数据库本身不会替产品判断偏好真假、经历重要性、遗忘与性格成长。

## SQLite FTS5 + BM25 的能力与边界

SQLite FTS5 是全文索引，BM25 对命中的文本排序；SQLite 此函数的分数越低匹配越好。unicode61 按字符类别形成 token，不能假定它能分出中文词；trigram 按连续三个字符切分，MATCH 中不足三个 Unicode 字符的查询不命中。[SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html)

对 Bayper 的工程含义（推导，未实测）：

- 可以用普通记忆记录作为事实来源，FTS 作为可重建检索索引。更正、删除及停用旧理解，需要同时约束正常读取与检索，不能只更新聊天上下文。
- 中文不能直接照搬英文默认 tokenizer。要验证中文切词后索引、合适的 tokenizer/查询策略；trigram 是子串方案，不是自动理解中文语义的替代品。
- “我最近不想被打扰”与“少主动找我玩”可能缺少相同检索词。关键词改写或语义检索是否必要，应由实际样本证明。
- BM25 不是记忆的重要性、真实性或应保留多久的评分。明确纠正、当前有效偏好、来源授权与遗忘规则应独立于相关性分数。
- 角色底色、关键行为约束和当前重要偏好应有明确的读取路径，不能因一次搜索没命中就消失；Herdr 必需通知更不能依赖记忆检索。

## 路线比较（Codex 工程评估）

| 路线 | 对 Bayper 的优势 | 主要代价与缺口 | 当前判断 |
| --- | --- | --- | --- |
| SQLite 记录 + FTS5/BM25 | 本地记录与明确更新规则容易核对；关键词命中可解释，检索本身不要求 embedding 服务 | 中文切词、同义表达与语境联想需验证；遗忘与冲突管理仍需实现 | 最值得先验证的基线 |
| SQLite + 全文与向量混合检索 | 保留确定关键词路径，同时补充相近含义召回 | 多出 embedding、向量索引、版本迁移与结果融合；不同模型服务未必提供 embedding | 基线出现实质召回缺口时再加 |
| 时序图/Graphiti 路线 | 可表达多实体关系、事实在什么时候有效 | 引入图与语义处理、模型调用及更多维护职责；个人桌宠需求尚未证明必要 | 暂不作为首版默认 |
| 直接采用 Letta/Mem0 等完整框架或平台 | 复用分层与记忆整理能力 | 需核对运行时、提供商、授权、修订/删除语义与接入成本；不能假定契合本地桌宠 | 作为参考，尚无直接采用依据 |

向量是检索补充，不必取代关系记录，也不必马上部署独立向量数据库。此处没有选定 SQLite 扩展、embedding 模型或框架；具体库的维护状态、许可与 macOS 接入需在采用前单独核实。

## 比选型更先明确的记忆要求

以下是由 PRD 导出的验证重点，具体实现待后续计划：

1. 来源可区分：直接聊天、共同互动和获准的外部会话；分析结果可保留初步判断身份。
2. 用户明确纠正及时生效，旧推测不能经检索或重新导入再次被当作现行偏好。
3. 重要偏好与共同经历长期保留；琐碎细节淡忘与历史记录物理删除是不同决定，尚未指定保留期限。
4. 外部分析关闭、目录权限撤销、来源文件删除与 Bayper 已有记忆处理分别定义，不能让数据库或框架默认行为替代产品决定。
5. 三层性格与当前关系状态可持续保存；短期情绪不能直接覆盖长期底色。记忆系统不负责决定是否发送必须的工作通知。
