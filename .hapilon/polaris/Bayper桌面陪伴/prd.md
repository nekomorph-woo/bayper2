# Bayper PRD

状态：讨论草案，持续原地更新；尚未完成范围确认或进入实现。更新日期：2026-10-25。

## 产品定位与起因

Bayper 是基于 Herdr 插件的桌宠应用，首先提供有生命感、有性格、能互动的桌面陪伴，再通过动作与表现让用户感知 Herdr 中 Agent 的工作状态。

用户的初始动机：终端中的 AI Coding 过程随着时间变长，容易变得百无聊赖。Bayper 希望让这段工作与等待多一点趣味和陪伴，值得长期留在桌面上。状态感知服务于这个定位，不能单凭状态显示正确便认定核心价值成立。

当前首先面向用户本人，优先 macOS 自用；画风是细腻且保留像素颗粒的 2D 像素风，不需要 3D。暂无面向公众分发的要求。

## 核心体验方向

1. **日常陪伴**：用户工作时，宠物有自己的活动，主要用动作、表情和偶尔的短句表达，让用户感觉它持续存在；自主活动不能以干扰工作为代价。
2. **主动的小惊喜**：等待 Agent 时，宠物偶尔发起互动；如何辨认等待、如何控制频率、用户不回应时如何处理，仍需讨论。
3. **回应用户**：用户主动关注它时，宠物给予有辨识度的回应；用户可主动发起文字聊天。回应能够延续以往互动形成的熟悉感；具体入口、动作、聊天呈现及变化机制尚未决定。
4. **感知工作**：Herdr 的真实状态影响宠物表现。怎样兼顾角色性格与状态可理解性、怎样区分待用户介入与普通等待，留待业务规则阶段细化。

上述是用户需求的整理，不是已冻结的功能列表、动作清单或正式验收 Case。

## 模型能力：已确定目标与待定边界

已确定接入 OpenAI API 兼容服务的方向，用于增强桌宠生命感和个性。此处“兼容”是产品接入需求，尚无具体服务的实测结论，也不承诺所有兼容服务能力一致。

已明确产品需要文字聊天、以往互动的记忆，以及逐渐形成的熟悉感与性格。模型如何支持这些能力、是否参与自主行为选择、首版做到何种深度，仍待讨论。还需讨论用户可配置的接入信息、调用开销预期、模型暂不可用时的体验，以及哪些信息可以发送给模型。

本次需求不自动授权读取或上传终端正文、代码、屏幕内容，也未确定模型能够控制 Herdr、执行系统操作或任意扩展宠物行为；相关能力若有需要，须单独讨论其产品价值与边界。

## 性格与记忆

已明确：日常表现与主动聊天是同一只宠物的两种相处方式，应延续之前互动，而非每次重新认识用户。用户希望性格与熟悉感能在相处中逐渐形成；记忆的保留粒度与实现方式尚未确定。

待讨论：

- 初见时是否已有性格底色，由用户选择还是宠物自行呈现；哪些特征相对稳定，哪些会随经历成长。
- 值得记住的内容：用户明确偏好、共同经历、称呼、互动习惯等只是候选，尚未选定；不把所有聊天细节自动视为长期记忆。
- 记忆如何体现在动作、表达、聊天与主动邀请中；如何表现熟悉，而非反复复述过去。
- 用户能否查看、纠正、删除或重置记忆；记忆失准、相互冲突和遗忘时如何表现。
- 不依赖正在打开的同一次聊天，仍能保持多少关系连续性；离开、重启及更换模型后的具体规则待定。

## 全局对象骨架（Codex 整理，待讨论）

- **用户**：与宠物共处，主动互动，也可能忽略其邀请；已明确不希望工作操作受影响。
- **宠物**：有角色表现与行为，能够回应用户、主动活动、文字聊天并感知工作；性格随相处逐渐形成，初始底色、变化规则与生命周期待定。
- **互动经历**：用户与宠物以往的行为与回应，为熟悉感和性格发展提供连续性；保留哪些内容、如何更新与遗忘尚未确定。
- **Herdr 工作上下文**：包含 Agent 与会话状态；与宠物的数量及归属关系待定。
- **模型服务**：为个性表现提供能力；它与日常动作、真实工作状态的职责边界待定。

这只是 PRD 的全局业务骨架，不设计数据库、API 或工程模块。

## 成功判断（候选，待体验细化）

- 长时间使用 Herdr 时，用户觉得陪伴与等待过程更有趣，并愿意让 Bayper 继续留在桌面。
- 用户能从互动中感受到相对稳定的性格，同时有适度变化，而非难以理解的随机反应。
- 偶发主动互动让人愿意接受，持续工作时没有频繁打扰或意外焦点切换。
- 角色表现能够传达必要的工作状态，不因表现力而误导用户判断 Agent 的实际情况。

以上尚无产品实现或用户体验证据，不设虚构的满意度、使用时长或通过率。

## 讨论边界与未决事项

当前只形成 PRD 并讨论产品目标、能力和全局关系，不进入实现、页面原型、正式素材生产或验收 Case 冻结。北极星依照 AGENTS.md 在实际使用中改进，暂不另建并行产品 PRD。

按讨论价值逐步推进：

1. 性格与模型的作用：性格底色与成长如何平衡，记住哪些互动，以及熟悉感如何表现；日常动作/短句与主动文字聊天的比例已明确。
2. 日常共处与互动：主动程度、回应方式、邀请被忽略后的表现，以及用户如何表达暂时不想被打扰。
3. Herdr 关系：一个或多个宠物、多个 Agent/会话如何关联，哪些工作变化值得表现。
4. 模型服务使用边界：必要信息、用户配置、调用开销、无模型或服务异常时的体验。
5. 根据前述决定形成首版核心范围、全局生命周期和体验判断，再选择开发切片。
