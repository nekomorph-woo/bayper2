# Bayper PRD

状态：讨论草案，持续原地更新；尚未完成范围确认或进入实现。更新日期：2026-10-25。

## 产品定位与起因

Bayper 是基于 Herdr 插件的桌宠应用，首先提供有生命感、有性格、能互动的桌面陪伴，同时必须通过动作与表现通知 Herdr 中 Agent 的状态变化。生命感与互动是产品定位，状态变化通知是核心必需能力。

用户的初始动机：终端中的 AI Coding 过程随着时间变长，容易变得百无聊赖。Bayper 希望让这段工作与等待多一点趣味和陪伴，值得长期留在桌面上。状态感知服务于这个定位，不能单凭状态显示正确便认定核心价值成立。

当前首先面向用户本人，优先 macOS 自用；画风是细腻且保留像素颗粒的 2D 像素风，不需要 3D。暂无面向公众分发的要求。

## 核心体验方向

1. **日常陪伴**：用户工作时，宠物有自己的活动，主要用动作、表情和偶尔的短句表达，让用户感觉它持续存在；自主活动不能以干扰工作为代价。
2. **主动的小惊喜**：等待 Agent 时，宠物偶尔发起互动；如何辨认等待、如何控制频率、用户不回应时如何处理，仍需讨论。
3. **回应用户**：用户主动关注它时，宠物给予有辨识度的回应；用户可主动发起文字聊天。回应能够延续以往互动形成的熟悉感；具体入口、动作、聊天呈现及变化机制尚未决定。
4. **必需的工作状态通知**：Herdr 中 Agent 状态变化必须通知用户。宠物可以以自己的性格表达，但不能因情绪、自主活动或不愿配合而漏掉、拒绝或无限拖延通知。通知的具体形式、时效、多会话归属与频繁变化的呈现仍待细化。

上述是用户需求的整理，不是已冻结的功能列表、动作清单或正式验收 Case。

## 模型能力：已确定目标与待定边界

已确定接入 OpenAI API 兼容服务的方向，用于增强桌宠生命感和个性。此处“兼容”是产品接入需求，尚无具体服务的实测结论，也不承诺所有兼容服务能力一致。

已明确产品需要文字聊天、以往互动的记忆，以及逐渐形成的熟悉感与性格。模型如何支持这些能力、是否参与自主行为选择、首版做到何种深度，仍待讨论。首次打开必须配置模型 API Key；其他接入信息、调用开销预期、后续模型暂不可用时的体验，以及哪些信息可以发送给模型仍待讨论。

Bayper 自动发现可用的 Coding Agent；外部会话分析默认关闭，用户可在设置页开启，并须明确授予对应会话目录访问权限后才分析。发现不等于访问或分析；分析多少历史或向模型发送哪些内容尚未确定。本轮只编写 PRD，不实际发现本机 Agent、读取或上传会话正文。模型控制 Herdr、执行系统操作或任意扩展宠物行为仍未确定；相关能力须另行讨论其产品价值与边界。

## 首次使用与模型配置

用户明确要求：首次打开 Bayper 时必须设置模型 API Key，配置完成前不进入正常桌宠使用，不能通过跳过配置进入无 Key 的首次使用模式。

OpenAI API 兼容服务的其他必要连接信息如何填写、是否需要实际连接验证才算配置完成，以及首次配置失败后的重试与退出方式，留待细化。本轮仅记录产品要求，不请求用户在 PRD 文档或对话中提供真实 Key，不调用实际模型。

首次配置未完成与使用中服务暂不可用是两个情境；后者的宠物表现、互动与恢复规则仍待讨论，不能因首次配置强制要求就推定后续断线必须退出应用。

## 性格与记忆

已明确：

- 初见时已有自己的性格底色，可以包含随机与未知感；用户通过相处慢慢认识它，性格不完全由用户预先设定。
- 此后通过相处逐渐成长。日常表现与主动聊天属于同一只宠物，跨次相处应延续之前的熟悉感。
- 记忆重点包含用户偏好与共同经历，并自然影响之后的动作、表达、主动邀请及聊天回应。记忆的保留粒度与实现方式尚未确定。
- 会话分析所得先作为初步了解，允许通过后续相处逐渐修正；不因单次任务就固定用户偏好。
- 琐碎细节可以自然淡忘，重要偏好与共同经历希望长期保留；用户明确纠正时，应及时更新记忆及后续表现。
- Bayper 维护自己的记忆；用户直接沟通、双方互动与经授权的外部会话分析都可提供来源，外部会话目录不承担 Bayper 的记忆存储职责。

待讨论：

- 在已认可的三层性格框架中，哪些具体特征相对稳定，习惯成长的幅度与速度，以及情绪如何变化和恢复。
- 怎样判断重要偏好与共同经历、哪些琐碎细节可以淡忘；如何在后续相处中自然体现记忆，以及何时需要提及过去。
- 用户明确纠正须及时生效已确定；查看、删除或重置记忆的入口与规则，以及冲突、误解和遗忘时的具体表现仍待讨论。
- 离开、重启及更换模型后的具体记忆与性格连续性规则。

### 性格成长的三个层次

用户已认可：

- **性格底色**：初见自带，允许随机与未知感，相对稳定。
- **相处习惯**：随共同经历与熟悉程度逐渐成长，形成与你特有的互动与表达。
- **当下情绪**：短期变化，为日常表现提供起伏，不直接等同于长期性格被改写。

普通互动允许不完全配合，例如躲开逗弄或表现自己的喜好；具体表现仍待设计。Herdr Agent 状态变化通知是必须履行的能力，不受这类自主性影响。

### 必需通知与角色表达

角色表达可以丰富，通知是否发生不能由宠物性格或模型自由决定。如何在模型暂不可用、动作中断、多 Agent 同时变化时维持通知，是后续切片需要验证的要求；此处未冻结工程实现。

这里的“通知”尚未指定必须采用 macOS 系统通知、声音或气泡。必须明确让用户感知状态变化，同时遵守不抢焦点、不影响操作的要求。不得以此前“偶发互动不能频繁”为由自行取消工作状态通知；频繁状态变化怎样清楚呈现需另行设计。

前期事件恢复实验显示断档期间的历史变化可能无法补回。产品要求仍保留为必需通知，后续须明确可观察事件、断连提示与恢复对账的边界，不能把恢复当前快照冒充所有历史变化均已通知。

## Coding Agent 发现、授权与会话分析

现行方向：Bayper 自动探索并发现可用的各家 Coding Agent，将对应的会话目录识别为候选数据来源。它仍通过 Herdr 感知 Agent 工作状态，但内容分析来源不再限定为 Herdr 中选定的项目或会话。具体支持哪些 Coding Agent、怎样发现可用性及定位会话目录，尚待技术核实。

已明确的用户控制：

1. 外部会话分析默认关闭。发现 Agent 不代表可以读取其会话正文或开始分析。
2. 用户可在 Bayper 设置页开启该功能；对发现的可用 Coding Agent，明确请求访问其对应会话目录，说明分析用途。开启功能不替代目录访问授权。
3. 获得对应授权后，才可将该目录中的会话内容用于构筑初步了解、记忆、偏好及有关经历；未授权时不分析对应目录。
4. API Key 的首次强制配置与外部会话分析的可选启用、目录授权是独立要求，配置 Key 不代表同意分析 Coding Agent 会话。

持续分析的更新时机、历史深度、授权说明与拒绝后的提示方式、开关关闭或撤销授权后如何处理已有记忆，以及模型接收原文还是筛选信息，仍待细化。授权要求不得被 Codex 的 master 调度权限或自动发现能力替代。

### 数据来源与记忆的关系

用户直接与 Bayper 的沟通、双方互动经历、经授权的 Coding Agent 会话内容，均可以成为记忆来源。外部目录保存的是来源数据，Bayper 需要独立维护提炼出的了解与记忆；具体存储载体和工程方案尚未确定。外部分析关闭不等于整个 Bayper 记忆能力关闭，直接沟通的记忆管理方式仍需细化。

用户已明确分析结果是可修正的初步了解，后续通过相处修正，不因一次任务固定偏好；明确纠正须及时更新。以下是 Codex 提出的具体整理原则，分类与历史表达方式仍待讨论：

- **明确表达与推测分开**：会话中明确说明的偏好，与仅从某次任务推测出的倾向保留区别。
- **工作背景可更新**：当前项目、任务与工具可提供当下话题，后续经历可以修正早先的判断。
- **过去背景与共同经历分开**：分析相识前的记录可以帮助了解背景，但不能冒称宠物当时亲自参与。分析到的内容如何与之后真正共处的经历联系起来，留待细化。

本轮修订记录：用户明确替换前版 REQ-12/13 的“用户选定项目或会话范围”方案，现以自动发现 Coding Agent、默认关闭分析、设置启用及会话目录明确授权为准；不保留旧方案作为并行配置要求。

### OpenAI 记忆参考

参考日期：2026-10-25。[OpenAI 官方 Memories 文档](https://learn.chatgpt.com/docs/customization/memories)区分历史聊天输入与由其提炼、独立保存的记忆，并提供输入来源的控制；该页也区分 ChatGPT 记忆与本地 Codex 记忆。这里借鉴来源与记忆分离、来源可控的产品思路，不照搬其存储格式、默认设置或处理时机，也不将 OpenAI 产品能力当作 Bayper 已实现能力。

前期技术研究覆盖状态与事件等固定实验，未验证各家 Coding Agent 的自动发现、会话目录授权、完整对话历史获取与内容分析。Herdr 状态、终端可见内容与各家 Agent 持久化记录应分别核实，按产品需要补足验证。

## 全局对象骨架（Codex 整理，待讨论）

- **用户**：与宠物共处，主动互动，也可能忽略其邀请；已明确不希望工作操作受影响。
- **宠物**：有角色表现与行为，能够回应用户、主动活动、文字聊天并感知工作；初见时自带可有随机性的性格底色，之后随相处成长，具体变化规则与生命周期待定。
- **互动经历**：用户与宠物以往的行为与回应，为熟悉感和性格发展提供连续性；记忆重点包含用户偏好与共同经历；重要内容长期保留、琐碎细节可淡忘、明确纠正及时更新已确定；具体规则待细化。
- **Herdr 工作上下文**：提供 Agent 与会话状态；与宠物的归属关系待定。
- **外部会话来源与授权**：自动发现的 Coding Agent 及其会话目录，属于默认不分析、需明确授权的可选来源；独立于 Herdr 状态接入。
- **Bayper 记忆**：从直接沟通、互动与获准来源中逐步形成并独立维护的了解、偏好与经历，影响后续行为；不是原会话目录的别名。
- **模型服务**：为个性表现提供能力；它与日常动作、真实工作状态的职责边界待定。

这只是 PRD 的全局业务骨架，不设计数据库、API 或工程模块。

## 成功判断（候选，待体验细化）

- 长时间使用 Herdr 时，用户觉得陪伴与等待过程更有趣，并愿意让 Bayper 继续留在桌面。
- 用户能从互动中感受到相对稳定的性格，同时有适度变化，而非难以理解的随机反应。
- 偶发主动互动让人愿意接受，持续工作时没有频繁打扰或意外焦点切换。
- Herdr Agent 状态变化得到必需通知，自主性不压制通知；角色表达不误导用户对实际工作状态的判断。

以上尚无产品实现或用户体验证据，不设虚构的满意度、使用时长或通过率。

## 讨论边界与未决事项

当前只形成 PRD 并讨论产品目标、能力和全局关系，不进入实现、页面原型、正式素材生产或验收 Case 冻结。北极星依照 AGENTS.md 在实际使用中改进，暂不另建并行产品 PRD。

按讨论价值逐步推进：

1. 性格与模型的作用：在三层性格框架中细化习惯成长与短期情绪；普通互动可有自主性，Agent 状态变化必须通知。长期记忆与遗忘方向已明确。
2. 日常共处与互动：主动程度、回应方式、邀请被忽略后的表现，以及用户如何表达暂时不想被打扰。
3. Herdr 关系：一个或多个宠物、多个 Agent/会话如何关联，所有应通知状态变化的表达方式、时效及断连恢复边界。
4. 模型服务使用边界：Coding Agent 发现与会话目录访问的授权体验、历史深度、外发信息、记忆管理、首次强制 Key 配置的完成条件、调用开销及使用中服务异常时的体验。
5. 根据前述决定形成首版核心范围、全局生命周期和体验判断，再选择开发切片。
