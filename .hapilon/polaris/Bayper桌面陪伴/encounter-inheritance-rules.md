# 发现、入住与记忆传承：当前组合方案

日期：2026-10-25。状态：PRD 讨论中的现行方案，未实现、未冻结验收 Case。

用户明确选择：以A版轻量相遇为基础，保留B版居所线索的连续性，加入C版同伴引荐。[原三版](encounter-inheritance-options.md)仅作为取舍历史，不再并列等待选择。以下细化由 Codex 根据该组合与既有需求整理为当前讨论默认；具体频率、时长和界面没有用户逐项确认，也没有实测。

## 发现：地方先有连续性，相遇保持轻量

1. **线索以居所为归属持续积累。** 同一处地方再次被提及时延续已经知道的环境、物品与生活痕迹，不每轮随机重写。补充内容和原线索冲突时应解释修正，不把同一地点换个说法当成全新发现。
2. **满员只带回居所信息。** 三个在住名额已占满时，不创建或展示新流浪者候选，不暗中生成等待入住的第四个身份；临时出门不释放名额。线索可以保留，但不保证未来一定对应某个角色。
3. **有空位后才形成具体相遇。** 仅从已随版本提供且素材已验收的角色中选择。先看线索关系与显露的粗粒度倾向，再保证与当前在住个体有足够辨识度；不现场拼凑未经制作的造型，也不需要用户填写造型参数。
4. **同伴引荐是相遇的一种来源。** 在住同伴可以在探索中带回线索，有空位后引荐新朋友；仍可自然偶遇，初始只有一只或全部临时外出时不必等待引荐。已经离开的个体只能通过已确认保留的书信/记录带来引荐，不凭空声称实时联系成功。
5. **线索阶段与具体相遇阶段分开。** 满员时可以说“那里似乎有位喜欢修旧物的旅人”，不能已经给它完整姓名、造型、人格并当作屏外同伴活动；有空位且正式相遇后才建立稳定候选身份。
6. **选择题可跳过。** 回答是当次话题与暂定倾向，可被后续互动修正；不答不会丢进度、不拒绝探索，也不自动改写长期偏好。问题围绕少量易理解的兴趣或外观倾向，不暴露310项参数。
7. **一次保持一个待处理邀请。** 不堆积多个催促入住的候选。重复线索合并到同一处记录，新的细节可以有回应，但不会每次都重发“发现新人”。确切主动频率、冷却和线索保留数量留待体验细化。

### 没有合适角色或来源时

没有符合线索的已发布角色时，只保留线索、继续已有陪伴，不虚构“新形象已准备好”，也不为了消耗空位把不匹配的外观强塞给用户。新增版本提供更多素材后可继续既有线索，但不保证某一条一定解锁新个体；已经出现的候选保持身份与外观版本，不因更新重新抽取。

外部分析未开启、未授权或模型暂不可用，不取消 Bayper 独立运行与现有陪伴。探索可围绕已有互动、记忆整理或普通活动；没有实际分析的内容不能声称来自用户工作目录。Herdr 是否在线不是发现新朋友的前置条件。

## 入住：轻量认识，由用户决定

| 阶段 | 规则 |
| --- | --- |
| 居所线索 | 保存地方的连续信息；不是新的在住个体，不占名额 |
| 正式相遇 | 有空位且存在合格素材时，认识一位稳定的新朋友；不要求多轮任务或刷好感 |
| 引荐或自我介绍 | 简短表达自己的习惯与底色，说明谁引荐；形象与人格不因每次介绍重抽 |
| 用户决定 | 接纳、稍后再说或拒绝；默认等待决定，不将沉默或选择题答案视作同意 |
| 接纳生效 | 再次核对名额，有空位才正式入住；分配独立身份与个人关系，引用已发布外观版本 |
| 暂缓 | 保留已认识的背景，暂停催促，不当作已经入住或开始亲密关系 |
| 拒绝 | 结束当前邀请，不惩罚、不立刻换人再问；具体能否重逢及间隔待讨论 |

若接纳时名额已满，先说明没有空位，不自动安排旧个体永久离开，也不把临时外出算作空位。若相遇后因版本或资源问题暂不可用，保留已经发生的关系事实并暂停入住，不静默换成另一张脸。

初始一只仍沿用既有要求；初始个体不是从前辈继承而来的“后代”。发现新朋友、永久离开和记忆传承是可分别发生的活动，不要求每次出现新人就有人离开，或必须有人传承才能入住。

## 永久离开与关系接续

当前建议默认：个体可以表达想独自闯荡的愿望，永久离开须用户明确确认；临时出门保持名额与归来连续性。用户确认永久离开后才释放名额，保留历史与可选择留下的记忆，不在离开前就把名额许给新人。

永久离开不作为获得新人、奖励或素材解锁的必须操作；拒绝新人、取消离开、暂不传承都不惩罚。旧个体是否还能联系或重逢仍待单独讨论，不用当前方案默认允许或禁止其回归。

离开和引荐不修改连接器或 Agent 归属；未表达的工作通知保持原事件身份。没有宠物在场时应用继续通知，不让新朋友必须马上入住才能恢复必需功能。

## 记忆传承：小行囊、有讲述者、可选择

1. **整理时机独立。** 在住个体也可以整理经历，为之后引荐或离开留下一份行囊；不必等永久离开才开始。永久离开前未完成传承不阻止保留已有历史，也不凭空生成已完成交接。
2. **内容保持克制。** 优先留下仍有效的重要偏好、少量共同故事、必要的同伴关系背景。具体条数与篇幅待体验确定；不默认复制全部聊天、工作会话原文或所有个人记忆。
3. **接收前给用户选择。** 建议展示简短摘要，允许选择部分、全部不传或以后再说；未选定接收者时只保存待交接内容，不因空位出现自动群发。可以先入住、后接收，不把交接变成入住门槛。
4. **提供者与引荐者可不同。** 引荐说明“如何认识”，传承说明“谁告诉了哪些事”；新朋友可以由一位同伴引荐、从另一位得到故事，不捏造共同亲历。
5. **接收后形成自己的理解。** 新个体保持自己的底色，不继承旧个体全部亲密程度或临时情绪；可自然说“听前辈提过”，然后通过真实相处修正理解与建立关系。
6. **纠正优先于旧内容。** 交接前核对有效记忆；接收时再次核对已撤销、已删除和已明确纠正的条目。传承内容需要保留来源，后续纠正能影响相关派生理解；具体存储与传播实现未确定。
7. **传承不传权限。** 故事与整理后的记忆不是原始来源访问授权；读取外部会话仍按当前目录授权与设置处理。关闭外部分析后，已有记忆怎样保留或清理仍按后续记忆管理规则决定，不能擅自替用户全删或全部继续分析。
8. **中断可继续但不重复接收。** 重启或暂时模型不可用后保留已经确认的交接进度；不反复重发同一份行囊，也不声称未完成的整理已完成。具体技术身份与事务方案留给后续切片。

传承素材不能决定新个体外观，造型数据库也不存放用户记忆。外观版本更新不重新创建旧个体，不借替换素材重置关系或重新导入已纠正故事。

## 待继续讨论

- 线索与引荐的主动频率、邀请冷却，以及同一候选拒绝后是否可以重逢。
- 已认识但尚未入住的候选是否有最长保留时间；满员后的既有邀请如何安静保留，不能继续制造新发现。
- 永久离开的个体是否联系/重逢，以及回归是否仍走空位与接纳规则。
- 传承摘要如何让用户轻松挑选，以及用户查看、纠正、删除对全部派生内容的影响范围。

这些缺口不在本轮用数据库表或代码强行决定。当前只推进PRD与设计资料工具，不开发正式发现、入住或记忆功能。
