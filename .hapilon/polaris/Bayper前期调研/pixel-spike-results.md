# 独立像素角色动画实测结果

日期：2026-10-25，Asia/Shanghai。合同：pixel-spike-cases.md。结论：**Codex生图→Claude Code处理/播放→Codex独立审查返修的闭环已实际跑通；本轮生成素材未达到正式像素动画质量标准。** 没有进入Bayper产品设计，没有确定其角色或动作。

## 实际分工与环境

- Codex Desktop当前会话内置image_gen实际生成四视图PNG，再以该图为唯一参考生成六帧眨眼/呼吸图集；均请求真实透明背景，没有CLI/API或视频模型调用。完整提示词在research/pixel-spike/prompts.md，原始输出已复制进项目assets/，没有伪称存在分层工程源。
- Claude Code CLI2.1.310，执行记录中的提供商模型为deepseek-flash。它实际用Read读取AGENTS.md、CLAUDE.md、技术合同与规格，再实现process.py及index.html；Codex没有编写或代改项目代码。实现约348行，两文件，无新增前端框架或依赖安装；Codex负责文档、版本、执行与独立量测。
- Python3/Pillow12.3.0处理真实PNG；本机IAB真实浏览器加载Canvas播放器，默认8帧/秒。GIF为120ms/帧、二值透明的有损演示，不与PNG播放器混为同一质量证据。
- OpenDesign本轮未调用：任务是位图生产和处理/播放验证，现有分工不要求每次所有工具都出场。没有启动Electron/Tauri、Herdr、原生悬浮窗或系统通知。

## 审查与返修

1. 两张原图均1536×1024 RGBA，但模型没有严格遵守排格：四视图第二只猫的尾部跨过384px分界。初版四等格切分截掉尾尖并在前一格出现碎片。Codex定位后，Claude改为实测空隙边界[0,354,780,1153,1536]，独立512×1024格拼为2048×1024。最终四视图alpha>=128像素数分别124487、116918、120791、114341，与对应原始裁区一致，未截断可见内容。
2. 动作原图确有六帧，不是六张重复图片。六格512×512，按同一0.5 NEAREST缩放为256×256，输出768×512图集。先用整体轮廓中心对齐，后改为脚部锚点，避免尾巴影响身体位置。
3. 中间锚点实现出现坐标系错误：裁切框内的x未换回整格x。Codex直接从输出图集量测到脚中心[182,157,153,175.5,157,152.5]，据此返修并复验。最终六帧脚中心为[128,128,128,127.5,128,127.5]，可见底边全部248；不以脚本自报的anchor字段作为独立证明。
4. 差异指标原先包含透明区域RGB噪点，已改为相同灰底合成后比较；最终相邻变化占比约12.22%–21.26%，首尾19.6%。这些数值只描述变化，不能单独证明循环自然或不自然。
5. 保留alpha，不自动抠图、不量化调色板或重画。原始动作图无完全不透明像素，四视图仅一个alpha255像素，角色主体约249–253；大量alpha0区域确实存在，也有半透明噪点/软边。原始SHA256与最终独立核对一致。平移裁掉的低alpha边缘像素数由measurements.json逐帧记录，不称无损转换。

首个开发调用在过长分析且尚未实现时由Codex中止，随后同一CLI会话继续；这没有中断Codex主会话。第二轮形成完整实现后已自行退出；一次对其发送中止信号时PID已不存在，没有实际中止该轮。后续按明确反馈返修。CLI会话连续性不等于绝对无中断保证，规格/原图/证据才是接续依据。

## 本轮判断

Codex同时主持调度和执行生图，确实没有自动结束主任务；生成之后仍完成Claude派发、审查和返修。其一般限制仍是工具等待、上下文压缩和可能的外部中断，需要落盘接续，不能承诺永不中断。

当前证据支持继续采用该分工进行素材实验，不支持“提示词一次生成即可交付”。下一轮若继续技术验证，应控制同一角色局部变化、动作节奏与像素网格，并对照短循环实际播放；不因此自动开始Bayper角色设计，也不将专业修整负担交给用户。
