# S05f 通知排队与呈现确认

Codex受托决定，依据PRD“播报与通知默认数值”。承接已验收connector-ledger与Herdr adapter。本轮把真实账本变化转为可供窗口展示的三普通位＋一加急位；后续再接正式桌面与连接页，不能把此服务测试称为实际可见时间达标。

## 范围与职责

新增app/notification-presentation.cjs（必要时一个小存储模块）、tests/acceptance/notification-presentation.spec.cjs。允许connector-ledger/store仅为持久原始通知优先级/接收时间与呈现确认做必要窄扩展；不要改adapter/transport/registry/main/store/renderer、其他任务、版本Git文档。共享SQLite，不复制账本事实，不调用模型、不建新connector SDK。生产建议350～500行，测试400～650行，先做清楚接口；超量说明真实原因，不压行数。

由main未来驱动tick/获取视图，renderer未来对真实已渲染条目回执，服务再markPresented。准备/排队/占位都不能当已可见。回执必须限定当前给出的presentationId和eventIds，不能随便传任意历史ID。窗口隐藏/重建前未回执的项目仍pending，实际显示开始才计算4/6秒。

## 业务约束

- 真实输入来自ledger持久pending及关联事实。每个事件保持instance/run/agent、接收时间与真实源状态，不合并不同Agent身份，不吞往返；快照/观测同义去重使用已有账本结果，不再推断服务端事件ID。
- P0最晚聚合0.5s、可见目标1s；P1为1s/4s；P2为2s/8s。批次开始和各事件deadline固定，不因新到达延长。普通待展示按deadline、接收次序；三位并行，满位排队。仅在同一稳定分组里追加具名子项，不能让“还有N条”替代来源和含义。
- 加急位置独立一位，P0不抢普通三位。已有加急气泡可追加不同来源/Agent子项，每新增条目回执后独立至少6s，旧内容不被重建/提前消失；当前待处理标记随最新事实更新，不定时重弹同状态。普通项回执后至少4s。用户主动关闭为例外，关闭不伪造状态已解决。
- 已接收到的blocked在0.3秒恢复，仍按原P0 deadline表达“曾需确认，现已继续”，不可因为ledger将historical降P1丢原截止点。需要原始优先级时明确保存不可变字段，兼容已有事件；已在断档恢复后补到的历史另按P1/P2并标历史，不能与在线已收到后恢复混为一谈。
- 模型/动画/角色精力不阻塞必需文字；本轮用明确事实短句与具名结构，无综合角色状态。不要把Herdr done写成“任务成功”。unknown明确未知。
- 原始事件历史与呈现状态持久，重复tick/回执/重启不重复标记。实际已呈现历史不会重新弹新提示；仍需处理的状态可以稳定标记，恢复不伪造离线期间已可见。未回执的原deadline不重置；离线造成超时明确为恢复积压，不声称仍满足实时指标。
- 极端积压不能无限加位或丢事件。准备视图可以具名分组，实际UI可读容量仍待后续验证；服务记录超时和原因，不用“入队=显示”掩盖。读取pending超过单页时有界分页/游标，不能永远只处理第一页或标记未读到事件已展示。
- dispose/窗口代次结束后的迟到回执不得确认新代次；同一事件只能被实际允许的呈现回执消费。没有UI回执时不提前删除。

## Acceptance Cases

真实SQLite＋正式ledger输入；模拟时间只推进调度，无GUI。本轮fake presenter只能证明回执/计时协议，不能证明真实窗口可见、无焦点或极端负载可读。

| Case | 构造过程 | 必须独立观察 |
|---|---|---|
| POL-NOTIFY-001 | 不同Agent P1/P2持续到达，三普通位满，再到P0 | 固定窗口/各自deadline不后移，P0独立位准备；普通不被抢，4s从回执算；全部身份可追踪 |
| POL-NOTIFY-002 | A working→blocked→working 0.3秒；多个P0错开到达且回执不同 | A原P0 deadline保留、已恢复表达无过时催促；加急追加稳定、每条6s，其他普通继续 |
| POL-NOTIFY-003 | 同事件重放、重复tick/回执；presented后关库重开；未ack时窗口重建 | 已确认不再新弹；未ack仍待呈现且旧deadline保留；旧代次/错误event回执拒绝；无丢历史 |
| POL-NOTIFY-004 | 超过ledger单页的大量事件、多实例相同局部ID、不可见窗口 | 每个事件具名来源/历史保留，有界推进无饥饿；记录真实未可见与超期，不以计数冒充可见；不增加超过3+1位置 |
| POL-NOTIFY-005 | SQLite呈现写入失败、角色休息/无角色/模型不可用、dispose | 失败可安全重试不重复呈现事实；通知不依赖角色数值/模型；回执/计时资源按代次清理 |
