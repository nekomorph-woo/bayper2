# S05j 必需事件进入真实桌面气泡

Codex受托接续S05i，目标是已连接Herdr的每次状态变化真正进入用户可见通知，不以设置页、队列或数据库写入替代呈现。沿PRD既定3普通+1加急、固定聚合窗、4/6秒阅读、1/4/8秒最大等待目标、无焦点抢占、无模型依赖与逐Agent归属。当前ledger和notification-presentation已有独立Case，生产主进程尚未接入。

## 最小实现边界

Claude负责正式代码和真实Electron场景测试；Codex审查。允许app/store.cjs/main.cjs/desktop-host.cjs及app/desktop/内必要通知窗口、preload、renderer、样式；复用既有子进程Prohibited非激活panel与共享SQLite。只为清晰职责新增小文件，预计生产约500～750行、验收约600～900行作为规模审查信号，不建设通用消息框架。不得更改角色尺寸/画风/聊天/活动默认值或版本/Git/文档。不得把本轮扩成自定义通知规则编辑器。

store同一SQLite连接组装notification-presentation。主进程以有界短tick（例如100ms）推动已有服务，不能拿5秒registry扫描当通知周期。不增加模型调用。tick不反复重建DOM、窗口或重新计算全应用快照；事件实际入账时间与真实可见ack时间分开保存。下线未知语义、同事件去重、恢复对账沿现有ledger，不能重新解释业务状态。

桌面子进程最多持有3普通+1加急通知panel，角色本体窗口仍约128pt，气泡与角色区域分别管理。位置贴近同屏角色但不遮挡角色/屏幕边界；拖动、多显示器边界沿现行几何能力。没有当前角色时必需通知仍需有可见位置，不能依赖角色资产ready。不能激活应用、打断聊天或强制切角色。系统锁屏/睡眠、窗口隐藏/未绘制时不ack不可见内容，恢复后按未呈现事实补显示。主动关闭例外使用正式closePresentation，不把未展示项偷偷标presented。

只把真实渲染且可见、内容未裁切的eventIds回执父进程；父进程验证所属子进程、presentationId及代次，拒绝旧回执。异步加载失败、窗口重建或进程重启不能丢待通知内容，也不能重复消费已真实展示事件。普通至少4秒、加急每条至少6秒，从实际ack开始。新P0追加时旧内容保持稳定，每条各自保留阅读时间；不能为了腾位置覆盖仍在阅读的事件。

气泡必须显示来源实例短ID/Agent名称/真实状态含义，finished为已结束或结果待查看，不称业务成功。无需额外输入焦点。多个事件可具名分组，但不能用“还有N条”代替来源与含义。超量内容应有可展开明细和明确未读状态；未进入可视区域不能批量ack。时效目标超出时如实记录overdue，不增加无限窗口、不压小字体、不丢事件、不伪造达标。单次常见突发的时效和可读性必须实测，不用1105条领域测试声称屏幕能同时读完。

## 验收Case

真实Electron主进程、正式通知服务、实际panel/DOM与SQLite，协议可用真实Unix构造事件，至少一Case使用隔离真实Herdr。不得只调用通知服务返回值当UI呈现。每批截图、真实ack及deadline/hold事实、退出清理保留。

1. POL-NOTIFY-UI-001：真实Herdr在线、逐Agent working/needs_attention/done进入气泡；来源准确、done不冒成功、不依赖模型。核对账本入队时尚未presented、真实显示后才presented。
2. 002：3个普通位置已满时P0进入独立位置，普通内容不被覆盖且保持4秒；连续P0具名追加，各自6秒；普通队列不饿死。按实际墙钟测1/4/8秒目标，不能用mock时钟自证真实延迟。
3. 003：短暂变化往返、重复传送、重连快照/events_lost恢复：不同真实变化保留、同事件无重复气泡；已恢复的待介入仍说明曾需确认现已继续，不留过时催促。
4. 004：通知窗口未ready、子进程重建、系统暂停、迟到旧ack：不可见不记已展示，恢复按同事件事实继续，已展示不重复；气泡与角色生命周期清理正常。
5. 005：边缘位置、小屏/多条内容的真实可读性，无焦点抢占、角色128pt不变、当前聊天不关闭。主动收起与超量明细不得误ack隐藏项；完整退出无残留窗口/订阅/数据库写入错误。

本切片待S05i独立验收与提交后派发，GUI独占。若实现发现当前通知服务语义不支持按可见子项逐条收束，先复现并最小修复，不降低Expected。

## 实施中补充的边界 Case

这些是原有“真实可见、可恢复、不漏通知”约束的可执行展开，不新增产品概念：

6. 006：可见回执在途时追加事件导致视图 token 变化；拒绝旧 token 后，同事件能自动重试，只确认一次。
7. 007：SQLite 暂时写入失败持续超过五轮重试，恢复后无需新事件也能完成回执；不能因次数耗尽永久挂起。
8. 008：锁屏后迟到的窗口 shown(true) 不解除系统暂停与阅读时间冻结。
9. 009：尚未接纳任何角色时，连接器必需通知仍能真实显示；不以素材或角色存在为前提。
10. 010：420pt 有限窗口内，三普通位与六条长 Agent 名加急通知并存。默认不点击、不滚动仍逐条自动可达；当前页在最短阅读期内稳定完整可见，不能随普通位退场/补入扩大又收缩。另批验证展开长明细的滚动路径。超出物理容量的延迟必须保留审计事实，不把延后展示说成满足一秒目标。

验收应同时看实际 DOM 几何、带时间的可见性采样、截图与数据库事实。仅有 hold_until 与 acknowledged_at 的差值不能证明该期间内容持续在屏；代理自动化检查也不等于用户亲自阅读确认。
