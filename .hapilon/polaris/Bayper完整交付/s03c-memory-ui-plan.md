# S03c 本地记忆查看、纠正与删除

Codex受托确认，延续s03b-window-plan第二切片，依据PRD及memory-and-sharing.md。不是自然语言记忆代理，不改变默认共享规则。目标是用户可以在真实窗口看见本位Bayper有效记忆，明确选择后离线纠正/删除，并使在途回复和当前可控旧展示立即失效。

## 交互与职责

- 当前管理窗提供有明确角色归属的“记忆”入口，已结识角色可选，不自动改变当日名单或同屏角色。采用独立小面板/局部区域，不把记忆状态塞进已有701行chat-panel；保持1200×800、960×680下操作可见、只有条目列表局部滚动。
- 显示实际有效记忆正文、类型及简洁来源语义（本人直接告知/初步了解/听某位说过），不向普通用户堆factKey、source hash或检索分数。空列表说明当前没有可用记录，不宣称用户从未说过。不显示已删除/失效条目，不用演示数组。
- 必须分页可达所有有效项，不能静默只列现有listMemories的200条。可以新增窄listMemoriesPage接口（稳定排序、每页约30条、上一页/下一页和hasMore），沿现有SQLite查询，不引通用分页框架；现有listMemories行为保持兼容。修改后重置当前页并刷新。
- 明确选中条目后可编辑正文并保存；删除默认范围为同一理解的已有持有者/派生项，提供“仅这位”选项，说明一次范围。用户按明确按钮即授权，不额外重复弹确认；保存/删除失败不清空编辑输入、不先报成功。
- 主进程验证受信sender、已结识角色、所选条目真实归属及当前版本。只暴露list/correct/forget具名IPC，不暴露通用memory执行器、SQL、来源控制或任意信任级别。纠正/删除不发HTTP、不消耗亲密/精力/心情。
- 防止旧编辑覆盖新理解：列表回传稳定条目ID/版本（内部使用），提交时若条目已变更/删除明确刷新并要求用户重看，不能凭旧factKey覆盖最新内容。需要时可在memory服务事务内加可选expectedVersion检查，保持旧服务调用兼容，不大改记忆策略。
- 本地事务完成后向renderer发带受影响角色的记忆变更事件。相关记忆列表刷新、清掉当前可控的旧聊天显示/保存提示；在途回复沿已有contextVersion判stale，不能显示或落库。不要清空无关角色聊天/记忆，不修改聊天原文/外部文件。再次显式查看历史属于原始记录，界面应区分“历史原文”与当前有效记忆，不能自动将旧历史当作新回答；不新增一套聊天删除系统。

## 范围与规模

允许app/main.cjs/preload、renderer必要接线与新增memory-panel小模块、memory.cjs/memory-store.cjs的窄分页/版本检查、tests/acceptance/memory-ui.spec.cjs及必要memory服务回归。禁止chat/model策略、desktop、external-sources、assets/tools/原型/版本/Git/文档/.env；不做自然语言删除/自动分享/目录读取。生产约300～450行、场景约250行是审查信号，不压行不堆抽象，超出说明必要性。

仅在历史UI任务49990完成并经Codex核对后派发；避免同文件写者。允许隔离真实Electron/SQLite和本机受控HTTP，不真实模型、不私人数据。源正文通过UI聊天的受控候选或测试fixture创建，需明确哪些初始大量数据只是为了分页场景，不能把seed当作真实提炼验证。
