# S06c 日常与探索的持久生命周期

Codex依据PRD及companionship-rules.md、state-and-rhythm.md受托确认。承接S02陪伴与S06机会，不另创业务状态。目标是真实业务入口可开始/暂停/恢复/结束日常与探索，结算正确并保持单一桌面位置；本轮不接模型/故事/主进程定时器，随后由同一正式入口接应用。

## 范围与维护成本

允许修改 app/companionship.cjs、app/companion-store.cjs；新增一个职责清楚的app/character-activities.cjs或activity-store.cjs（确有需要可两个但先解释职责），新增tests/acceptance/character-activities.spec.cjs，以及相关companionship既有Case必要补充。禁止main/store/preload/renderer、机会/预算/关系事件模块、插件、素材、Git/版本/文档。其他开发者占用main与GUI，本轮无GUI/真实模型。使用同一个SQLite连接，事务与现有store约定兼容。

生产新增建议350～500行、测试450～650行是审查信号，不压缩语句凑数。先理解现有结算与自然节点，不复制整个陪伴服务、不建通用workflow框架；如必须超出边界先报告实际原因。所有代码与测试由Claude实现，Codex独立验收。

## 业务与接口契约

- 通过companionship服务提供清晰的活动请求/自然节点开始/推进/暂停恢复入口，snapshot反映活动身份、种类、状态与有效进度。持久化稳定activityId及角色、duration、activeElapsed、锚点和启动额度；一次ID不能更换角色/类型。参数仅来自可信main调用，模型不能自由写数值。
- daily时长5～15秒（默认10秒），exploration15～30分钟（默认20分钟）。日常全局滚动小时1次；探索全局4小时1次/24小时2次、最多1个未完成探索含暂停。人数不放大额度；只有当日名单有新启动资格，daily精力>30、exploration≥60。请求失败或待自然节点尚未执行不扣精力、不消费启动额度；重复调用不能重复开始。
- 聊天/待交接期间不新启动自动活动。当前同屏者探索必须在当前短自然节点结束后才开始，并原子切换至合资格接替者；没有接替者则不启动。非同屏者可探索，不影响当前角色。探索者不再同屏。daily本轮也在明确自然节点提交开始，避免不经过节点的动画抢占；当前节点取消时不算执行。
- 实际执行开始，先结算旧时段，再日常-2/探索-8一次，与活动记录/启动额度/角色位置同事务。活动执行时不叠加同屏耗时、不按waiting恢复；暂停后按真实位置恢复或互动规则。不得把exploring标志置true却仍按waiting持续回血。完成也不重复扣除，不自动加亲密/心情或伪造故事。
- 使用实际有效运行间隔推进，不通过调用次数推进；到时完成，余下时间按完成后真实模式结算。时钟回拨不产生负进度、不提前额度。完成ID重复推进无副作用。
- 主动找探索者聊天优先：开始互动前暂停探索、保存进度，再交接到单一同屏；聊天结束仅在有当日资格、非同屏且无聊天冲突时恢复，否则继续暂停。暂停不释放探索并发名额。跨日换出名单、关闭/锁屏/休眠均暂停且不补做离线进度；进程重建后未完成活动先暂停。恢复同ID不再扣精力/不再占一次启动额度，不额外触发API。探索回来不挤走当前角色，按现有候场规则。
- 保持原有名单、临时聊天、低精力轮换、数值恢复行为。关库再打开、事务失败、活动后重建模式都不得双结算。运行时活动状态应由同一事实源派生，不同时维护不一致的两套mode。

## Acceptance Contract / Oracle

使用实际SQLite和正式companionship入口，注入时间仅用于时间推进，已接纳构造角色/固定名单；不mock核心活动与数值逻辑。外部API与GUI本轮未执行，不能宣称生产应用闭环。

| Case | Given / When | Expected与独立观察 |
|---|---|---|
| POL-ACTIVITY-001 | 两位已结识名单角色，发起同屏探索；自然节点前/后读取快照和数据库，重放同ID | 节点前无扣除额度；之后探索者退出、接替者单独显示，精力仅-8，重复不再扣；无接替者/不在名单/低精力/聊天时不能开始 |
| POL-ACTIVITY-002 | 合法日常开始，推进10秒并重复完成；同角色此前陪伴一段时间 | 陪伴段按-6/h，日常仅-2，执行段无额外耗时；结束后回真实模式；滚动1h额度跨自然日/重建不重置 |
| POL-ACTIVITY-003 | 探索运行5分钟后主动聊天，等待再结束，切至其他角色后恢复到完成 | 有效进度只累计运行段，聊天单一同屏不改变名单，暂停/恢复不二次扣；结束不挤走当前角色、不自动产出线索 |
| POL-ACTIVITY-004 | 探索中锁屏/关闭、真正关库重建、时钟回拨和跨日退出名单 | 离线只恢复精力、不推进探索；重建暂停、不自行完成；无资格不恢复；有效恢复保持ID、额度与已执行进度 |
| POL-ACTIVITY-005 | 多角色尝试并发，4h/24h边界重复启动，DB触发器故障注入开始事务 | 全局并发/滚动上限独立于角色；暂停仍占并发；失败后精力、位置、活动记录与额度一致回滚，可在同ID安全重试 |
