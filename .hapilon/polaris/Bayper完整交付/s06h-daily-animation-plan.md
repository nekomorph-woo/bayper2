# S06h 日常动作的正式播放与恢复

Codex受托确定下一切片：完成S06d中仍明确未覆盖的日常真实动作，不扩大活动频率或模型调用。S05j占用main/desktop和GUI时不得开始实现。现有凛stretch-pixel-v2已通过独立播放器的导入与约128pt尺寸检查，但仍是候选；本切片以正式桌面衔接、实际视觉审查和活动生命周期验收决定是否发布，不先打开能力门。

## 边界

代码继续由Claude Code实施。读取AGENTS.md、STYLE.md、S06d计划与审查，复用现有活动服务、activity-runtime、desktop-assets、桌面播放器及既有Case，不建设第二个动画引擎、调度器或资源注册框架。主要改动限定desktop-assets、桌面renderer现有播放控制和必要主进程信号；活动服务只有真实复现的不符合既定规则处才修改。不要改变连接器通知、模型默认频率、角色名单或其他角色资源，不把凛的图用于其他角色。代码规模优先控制在一个小切片，派发时根据S05j最终接口核定文件清单。

## 动作契约

- 凛的idle、wave与stretch采用共同参考尺寸、固定地面锚及统一显示比例；不在动作切换时逐动作fit，也不因新动作加入而放大本体超过约128×128pt。角色身份、像素密度与脚位需以实际画面对照。
- scheduled仍不扣精力；正式画布自然节点开始同一daily后才按现有规则扣一次。真实stretch播放完成与活动有效时长都满足后，在自然节点回到idle；不能单纯按计时器宣称动作完成，也不要在整个活动期间高频重复伸展。
- 动作不可加载、尚未ready或画布不可见时保持能力门关闭/按既有取消暂停规则处理，不能退回idle或徽标冒充日常动作。仅凛经本轮验收的动作获得可用资格。
- 聊天、切换角色、系统暂停和素材故障沿既有多原因暂停机制。恢复同一活动ID、剩余有效时间，不重复扣费、不补算离线、不另抽一次活动。动画从适合衔接的节点恢复，不能因反复恢复刷动作或卡住活动。
- 必需通知保持独立；加急气泡不抢角色活动或聊天，不借P0重启daily。探索动作仍是单独未完成项，不借本切片宣布正式探索动画完成。

## 验收

沿POL-ACTIVITY-RUNTIME-001/003/004原Expected补覆盖，不删除原NOT_COVERED历史。实际运行正式Electron主进程、SQLite和桌面renderer，记录允许的时钟/随机fixture；不能直接调用服务当作正式UI链。

1. scheduled到节点启动、一次精力变化、真实动作帧序列、活动完成回idle；截图/关键帧序列核对128pt、脚锚、脸发服装一致、无裁切闪白和单角色。
2. 动作过程中开始聊天再结束、手动切人、锁屏恢复和退出重开；检查同ID进度、扣费次数与多原因阻止恢复，不把墙钟当有效活动时间。
3. 缺帧/加载失败和未ready不启动扣费；真实故障恢复按原活动事实处理，不篡改正式素材源文件进行测试。
4. ordinary/P0通知到达时活动和聊天保持、来源通知正常展示；S05j相关Case做必要回归。
5. 未发布动作的其他角色仍明确不可用，无借图、无自动fallback；合法自动机会不提高频率。

Codex独立检查实际diff、运行结果、真实尺寸画面和接缝后决定资源发布；Claude自述或单独播放器通过不足以通过。所有批次保留日志、截图、数据库事实和清理结论，退出后没有测试窗口/进程/隔离目录遗留。未达到视觉标准则继续保留候选并返修，不把能力门开关当作完成Goal。

## 实际资源兼容性前置检查

2026-10-27 Codex核对现行manifest：idle-pixel-v2/wave-pixel-v1为256×384、output_foot_anchor(128,376)；stretch-pixel-v2及listen-pixel-v3为320×384、(160,376)，neutral-height均298。desktop-assets.buildDisplayPlan要求脚锚完全一致且使用idle的frameSize，不能只在getAnimations里增加stretch就认为可用。实现前统一公共画布/地面坐标：优先使用已有sprite-pipeline从保存的源图导出兼容尺寸的非破坏版本，或在已有播放器中采用简单明确的画布偏移；选择需保留一致线性比例和同一地面锚，禁止逐动作fit、静默拉伸、忽略footStable检查。派发前后对照旧待机实际身高，原已接受源图和导出保留，不让工具重新绘制像素。

sit-pixel-v2采用explicit-region-anchor、spec.output_ground_anchor(160,370)，不是output_foot_anchor字段；它不属于本轮伸展范围，不能顺手纳入既有站姿加载器，也不能把缺失字段当0。后续休息动作切片须另核对接地以下的裙尾空间。本轮仅解决当前站立日常动作的坐标兼容，不扩成通用资源引擎。

已完成最小兼容预处理：既有工具导出stretch-pixel-v2-canvas256（及后续互动用listen-pixel-v3-canvas256），8帧均与旧导出去除两侧各32列全透明空白后的RGBA逐字节一致，scale/时长/源SHA不变，脚锚128/376。本切片优先直接加载stretch兼容候选，不必扩宽idle/wave或为尺寸差异增加播放器抽象。该检查只解决坐标兼容，实际动作质量和正式集成仍按上述Case验收。
