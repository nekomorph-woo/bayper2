# S04e 将授权来源分析接入实际应用

S04d验收后已派发并完成，最终结果见s04e-review.md；本稿保留Codex受托确定的业务与验收合同。PRD目录授权、独属初步记忆和全局低频调用是验收来源。既有S04c/S06a/S06b通过只证明模块，本轮必须验证正式主进程调用链。

## 目标与边界

实际设置授权且开启分析 → 合资格名单成员抽中自动机会 → 有界选择获准会话 → 既有source-analysis一次请求 → 初步记忆落同库。默认关闭绝不枚举正文/网络；锁屏、聊天、撤销与退出及时取消且迟到结果不发布。不是另外的高频后台扫描器，不因来源数量增加机会或额度。

预期改动app/store.cjs（内部同库组装）、app/main.cjs（现有心跳与生命周期）、一个小app/source-automation.cjs、tests/acceptance/source-automation.spec.cjs。仅必要时窄改source-settings取消通知接口；不重写来源解析/提炼/记忆/预算模块，不修改PRD、版本、GUI设计或Git。实现由Claude完成。预计生产新增200～350行，不建第二个调度框架，不暴露db/Key/permit给renderer。

## 组装约束

- 使用store已有SQLite实例创建单个automatic-budget、reader、source-analysis，持久预算的崩溃恢复只在应用启动边界执行一次，不每次来源变化重置。凭据使用现行safeStorage读取入口，不复制.env解析，不写明文。
- 一个应用级automatic-opportunities，现有心跳触发evaluate（它自身负责30分钟、25%和busy）；后续活动路由复用此入口。本轮唯一已接入的自动用途为来源分析，不声称日常/故事/探索已接好；调用失败不在同机会换文件再发。
- 在分析开关、名单资格、未互动/未暂停等门通过后，才对一个有效已授权目录签发许可并调用reader.listSessionFiles；选择一份已支持的会话。持久化轮转游标只存目录ID/相对路径等最小元数据，避免每次永远选第一份已处理文件；不得另建全目录常驻watcher或全部正文缓存。枚举沿用现有限制，截断如实保留，不能声称200之外均已分析。
- 只调用既有source-analysis.analyze一次，它负责预算发送、checkpoint和记忆发布。不在外层再预扣一次API预算，不把未发送的跳过算发送。source-analysis现有初步推测与来源追踪不降级成直接用户记忆。
- 关开关/撤销要让正在运行的source-analysis取消；重新启用不立即补抽。当前目录许可、角色资格、记忆context版本在发布前仍须真实复核。用户聊天开始即暂停自动入口并取消当前分析，聊天结束/系统全部暂停原因解除后从至少30分钟后继续，原因叠加不能过早resume。退出先dispose并等必要清理再关库，晚返回不访问已关DB或发布记忆。
- 服务构造不意味着用户已配置模型或已接纳角色；启动配置页无凭据/无角色时安静跳过，不能后台真实请求。权限授予与开启开关分开，继承S04d真实确认。

## Case与观察（具体测试接口由Claude先核对）

POL-SOURCE-AUTO-001：真实Electron主进程、同库、构造受支持会话与本地HTTP模型fixture；默认关闭跨多个加速机会无正文读取/HTTP/新记忆。通过设置IPC完成fixture原生确认并开启后，受控时钟/随机仅加速机会，正式心跳路径产生一次请求和一位角色初步记忆。独立观察HTTP请求次数、SQLite来源/角色/预算记录与记忆页面结果；不直接调用analyze冒充应用链路。

POL-SOURCE-AUTO-002：HTTP延迟期间关开关、撤销、开始聊天、锁屏分别执行，迟到响应不发布。显式聊天正常走原聊天链且不占自动预算，解锁但仍聊天时不恢复；所有原因解除不立即补抽。Key与会话正文不进入日志/renderer未授权字段。真实系统锁屏可用主进程powerMonitor事件fixture，明确边界，不锁用户电脑。

POL-SOURCE-AUTO-003：多授权目录与多个文件，连续合法机会轮转，不永久只扫第一文件；重复来源/已删除记忆不学回，文件编辑触发已有保护，来源坏文件不会无限同步重试。关应用并真正关库重开保留额度/游标/去重，但不补离线任务；重新打开默认配置保持授权真实状态。

POL-SOURCE-AUTO-004：模型配置缺失/失效、预算耗尽、无合资格角色时不发送。实际fixture失败仅消耗真实已发送尝试一次，不立即重试；退出期间HTTP晚响应无落库/未处理异常。明确模拟时间、HTTP、原生dialog与真实Electron/SQLite边界。生产流程通过后，再按用户已授权DeepSeek配置做至多一次必要构造数据连通，不重复既有纯模型测试，不输出Key。

每次使用唯一证据批次，先保留失败；正式行为Case通过后才提交。实际手工/Agent界面体验标明操作者与范围。实施与独立验收已完成，后续S06d复用同一自动机会入口。
