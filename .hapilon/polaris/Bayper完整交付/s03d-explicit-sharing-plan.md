# S03d 用户明确转告的本地权限边界

Codex依据已获授权确认本切片，来源为 Bayper桌面陪伴/memory-and-sharing.md 的“默认不全员共享”“纠正与删除的简单范围”。现有memory.share拒绝所有派生内容再次转发，适用于保守内部分享，但尚不满足用户明确要求转告的例外。先实现可核验的本地业务能力，后接正式记忆管理/对话入口；本切片通过不代表用户可用共享全链路已完成。

## 设计与范围

复用memory.cjs、memory-store.cjs及真实SQLite，不建立新记忆库、权限框架或图数据库。现有share保守行为及旧Case继续成立；增加清楚命名的“用户明确转告”入口，调用者须给明确持有条目及其版本、单一已结识接收者。该入口之后只能由主进程在可信用户操作解析后调用，模型回复或记忆正文不能自行取得权限。API字段不是安全认证，本切片不声称已完成IPC权限。

用户可以从A向B分享指定条目，也可明确让B将听A说过的同一条转告C；保留最初来源与直接讲述者/派生关系，不将听说写成亲历。不给名单外接收者自动活动资格、不换桌面、不改变名单/数值/内容进度，不要求模型回应，不发待办。接收者已有同一有效事实时幂等，不覆盖接收者更新后的内容；冲突如实返回，不静默以旧转述覆盖。

增加按事实的持久“不要再分享这件事”限制，只存最小控制，不复制正文；对已持有的同一事实与派生条目生效，不将事实告诉未知角色。设置限制不会撤回已有记忆，结果可说明已有接收者，但只能基于已有关系。解除必须独立明确操作；普通转告不能偷偷解除。角色仅自己忘记后不得通过转述恢复；全局删除、纠正与现有版本失效规则保持。用户以后重新明确学习的授权不是本轮扩展点。

自动分享的主题白名单、名单资格、滚动24小时一次及全局预算由后续活动集成处理，本轮不接自动调度；现有share也须尊重事实禁止分享。全局“不要自动互相讲我的事”开关将在自动分享入口接线时实现，不能声称本轮已覆盖。

## Acceptance Contract

所有Case使用真实记忆服务/SQLite与构造数据；无网络、无GUI、无真实私聊。Runner为独立tests/acceptance/memory-sharing.spec.cjs，复用合理fixture，不复制整个旧suite。

| ID | Given / When | Expected / Oracle |
| --- | --- | --- |
| POL-SHARING-001 | A有日常片段与另两条私人/工作记忆；用户指定一条给已结识但名单外B | B仅获得指定内容、原来源及直接派生；C未知；SQL、检索、上下文核对；名单/数值不变；重复操作无新增/多次版本增加 |
| POL-SHARING-002 | B持有A转述；保守share与明确转告分别尝试到C | 保守入口仍拒绝，明确入口允许并保留A来源、B讲述；A自删除后仍能正确追溯，不能因父条目缺失丢失派生身份 |
| POL-SHARING-003 | 设置同一事实禁止分享后重开DB；A/B尝试继续转告；随后明确解除 | 限制持久、跨相关持有者生效，无新正文/未知者记忆；已有副本仍在；解除后允许；普通转告不解除；失败事务无半写 |
| POL-SHARING-004 | B曾只让自己忘记；A或C明确转告给B | 仍被防回流控制拦截，不绕过删除、不扣数值；全局删除后控制表无正文，旧entry/version不能成功 |
| POL-SHARING-005 | 用户选中后事实已纠正或删除，或recipient已有更新的同事实内容 | 旧版本拒绝，不覆盖新内容、不假成功；正确版本分享遵守当前事实；保持未知角色不被纠正操作告知 |
| POL-SHARING-006 | 非持有者、未知接收者、自己转自己、重复IDs、其中一条禁止、写失败 | 输入清楚拒绝，整批原子，无部分泄漏/上下文版本半更新；明确分享成功后接收者旧上下文失效 |

结果逐项记录实际观察和边界。独立复验新6项及现有memory、chat/source相关必要回归；正式GUI/自然语言和自动共享仍标NOT_COVERED。既有源码借鉴见memory-source-review.md：身份过滤、事实/派生关系与最小删除控制；本轮不增加语义模型或检索策略，后续语义定位另做基线对照。

## 派发纪律

仅允许app/memory.cjs、app/memory-store.cjs、tests/acceptance/memory-sharing.spec.cjs及确有必要的既有memory.spec断言；不修改main/桌面/活动/素材/版本/docs/Git。GUI正在被S06h独占，本轮不得启动GUI。最小生产增量预期约150～250行，规模是审查信号；优先在既有事务与数据入口清楚实现，不造通用策略/授权系统。Codex独立审查实际diff及结果，再决定接受。
