# S06e 作者故事节点与持久线索进度

Codex受托决定，依据PRD及clues-and-discovery.md。目标不是任意模型文本计数，而是以稳定作者节点保存已获得的了解；本阶段先完成进度与选择，下一阶段承接邀请呈现/接纳和服装解锁。完整后续需求保留，不把本阶段当作发现系统交付。

## 范围

新增app/story-progress.cjs（必要时拆一个清楚的存储文件）、tests/acceptance/story-progress.spec.cjs及测试构造内容。禁止改main/store/renderer、活动/机会、记忆、连接器、版本、Git和文档。接收调用方同一SQLite连接、固定版本内容目录、时钟；复用现有character_activities和relationships读取资格/实际活动事实，不创建独立DB、不模拟核心业务。先读现有持久活动及测试harness，避免重复造运行框架。生产建议250～400行，测试350～550行，必要增加先在报告说明，不压行数、不堆抽象。

正式目录的内容由Codex后续设计，本轮只用明确标注fixture的作者节点测试，不伪造已经发布角色或服装。不改app/content/characters.json中的development-candidate以便通过。

## 行为契约

- 作者目录包含稳定storyId、type(character/outfit)、targetId、ownerCharacterId(服装)、themeId、明确排序的nodeId/factId与作者正文、素材可用状态。不是运行时AI改写目录，API只收受信任调用方选定的节点ID，不能凭模型正文发明节点或解锁。
- 每次提交带activityId、narratorId、storyId、nodeId；必须存在正式活动记录、对应讲述者、daily/exploration且已真实completed。源活动只能贡献一个新有效节点；同一次活动的重放不重复推进。当前活动取消/运行中/不存在不能产生进展。名单资格由实际活动开始时已验证，不因完成后名单刷新丢掉真实经历。
- 全应用滚动24h最多1个新有效节点，角色/服装合用；时间由可信应用时钟提供，回拨不提前额度。不补离线份额。无额度时不持久化“已获知”，不得靠稍后反复提交旧活动形成欠账；活动结果被本次评估记录为跳过，同活动重试保持该结果。
- 稳定factId去重：同事实同义措辞/换讲述者只合并来源，不推进节点数或再占新线索份额。记录归属、来源活动、讲述者、获知时间；不自动写入全员记忆，不把版本故事当用户工作经历。
- 节点按作者顺序推进；跳到后一个节点、未知目标、重复节点ID/事实冲突拒绝。不能拿任意两句模型话凑完成。正常默认两节点，成熟条件以目录节点列表为准。
- 同时最多推进一条未成熟角色故事与一条未成熟服装故事；优先续已有进度，然后按目录稳定顺序选择。服装仅已结识角色，角色仅未结识目标。调用方可显式提供有待决定邀请/已拒绝角色的可信状态作为选择过滤，接口为后续邀请服务准备，不让renderer自由传以绕过。
- 素材不可用目标不作为可发现候选；已有进度保留且返回unavailable，不重置、转目标或假成熟。新版本内容恢复后继续同story/node身份。已成熟故事不再推进；暂无匹配返回空，不额外调用模型或当场重抽。
- 所有进度、活动结果、事实来源与额度变更同事务。失败可用同activityId安全重试；真实成功重放/关库重开保持结果，不泄露活动正文到日志。取消/删除个人记忆不应重置内容进度，此模块不直接调用memory。

## Acceptance Cases

使用真实SQLite、实际companionship入口建立/完成活动；可注入时钟和构造目录。不得通过直接写completed活动行冒充核心完成入口。

| Case | Given/When | Oracle |
|---|---|---|
| POL-STORY-001 | 已接纳a，作者两节点角色故事；a实际完成daily后提交第一节点，24h后完成另一活动提交第二节点 | SQLite事实/进度/来源一致，第一次partial、第二次mature；无邀请接纳或自动换人；未知/跳序/未完成活动拒绝 |
| POL-STORY-002 | 同activity重复、换讲述者同fact、同24h不同story；真正关库重开与时钟回拨 | 无重复进展/额度/新事实，合并来源不冒充新信息；超额活动跳过不排欠账，重启不重置份额 |
| POL-STORY-003 | 多角色/服装故事，已知/未知归属，待决定邀请/拒绝过滤，素材下架再恢复 | 一角色一服装进行、先续旧；已接纳目标/未认识者衣服不成为候选；不可用保留进度，恢复继续；空目录无虚构产出 |
| POL-STORY-004 | 实际数据库触发器在写进度/来源/评估阶段故障 | 同事务回滚，活动不被错误消费，重试一次成功；稳定结果/目录冲突不损坏已有内容 |

保留首次真实失败和修复结果，报告接口、Case映射及生产/测试规模。本轮仅Node，不GUI/网络/真实模型，不抢其他开发者文件；证据独立批次evidence/s06e-story-progress。Codex独立验收后再接正式内容与main，禁止自述完成整个故事系统。
