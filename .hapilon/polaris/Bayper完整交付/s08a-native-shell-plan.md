# S08a 正式窗口的原生布局与现有功能整合

Codex受托确认。用户要求桌面应用更native、主要内容单屏、减少滚动。依据Bayper窗口原型/native-rework.md与prototypes/desktop的已审查三页设计，现有生产S01页面不可作为最终产品。先把现有真实能力归位到固定窗口框架，不添加假故事/假连接/假衣橱；后续业务页随真实服务补齐。

## 范围

只改app/renderer/index.html、styles.css、app.js，可新增小型window-navigation.js；必要时改chat-panel/memory-panel的纯布局接线，但不能改变它们已验收的异步/归属控制。允许新增tests/acceptance/native-shell.spec.cjs及既有onboarding/companionship-ui/chat-ui/memory-ui/desktop测试中必要的导航步骤或定位器适配，保留原业务Expected/断言。禁止main/preload/services/SQLite/model/assets/tools/原型/Git/版本/文档。已有两个Claude任务独占connector/source-analysis/budget，不触碰。

先读取AGENTS/CLAUDE、native-rework、三个原型页面及生产渲染器。代码仍由你实现，不启动OpenDesign/CU，不改原型。现有原型只是视觉参考，所有显示必须来自现有snapshot/IPC。GUI本轮可独占（Codex已结束播放器）。只本机fixture模型，禁止.env/私人数据/远程API。

## 具体交付

1. 已接纳后用固定左侧窄导航＋紧凑页标题/工具栏＋剩余内容高度。三个真实入口小窝、角色、设置。未实现的故事/连接页暂不做假可用入口，后续补。首次配置→许愿→相遇仍保持真实流程，用紧凑居中单屏布局；不能删错误/校验。移除S01等内部阶段标签及重复长说明，保留候选素材必要标识。
2. 小窝首屏看当前Bayper、实际状态/数值、今日最多5位名单，聊天/换陪伴/安静休息可达。当前角色图可比桌面放大，但不铺满窗口。长介绍放角色页，去掉重复名单段落。名单局部滚动仅在确有必要时。主操作和气泡错误区固定可见。
3. 角色页展示已结识列表及选中角色详情，允许选中名单外角色发起临时聊天、打开有明确归属的现有记忆面板、改昵称、设置固定陪伴。显示来自实际snapshot，不把“浏览角色”当切换桌面/改名单。既有固定/昵称控件语义不变。尚未完成衣橱不伪造服装解锁，先不扩该页。可采用详情内小分段控件，避免所有表单同时堆叠。
4. 设置页先呈现已有模型配置状态和检查连接能力；如果现有可用修改配置流程已存在就保留入口，没有则明确此切片不新增服务，不能自行假设保存API。身份Key不显示；连接检查错误/进行中/完成状态可见。后续来源授权有真实服务接线时再加入。
5. 当前聊天固定面板、消息局部滚动、输入框持续可见；记忆面板保持真IPC/分页/离线纠正删除，960×680下控件可达。导航不意外关闭在途聊天、丢草稿或改角色；Escape/关闭焦点返回真实发起按钮。页面按钮隐藏时焦点落在合理当前入口，不聚焦隐藏元素。
6. 1200×800与960×680（包含原生窗框）document均无纵横滚动。不靠裁切/整页overflow:hidden遮掉功能，不缩小辅助文字到12px以下；主要14px系统字体。使用现有暖灰/低饱和绿、细分隔与紧凑表单，避免大卡片/宣传页大标题、假macOS窗口灯。真正长内容仅局部滚动。动画角色仍独立桌面，不改变128pt约束。
7. 原有DOM ID可保留，测试通过真实导航到相应页再操作；禁止为旧测试隐藏重复按钮或造一套测试页面。生产交互从固定导航进入，不能只用evaluate改state替代用户流程。

约新增或改动生产400～650行是信号；整合已有HTML/CSS优先删除重复，不叠一千行覆盖样式。测试复用项目fixtures，不建通用路由框架/状态管理库；若无法小范围完成，先报具体边界。
