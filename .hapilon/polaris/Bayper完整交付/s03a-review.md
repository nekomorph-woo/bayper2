# S03a 独立审查

本轮尚未接受。Claude Code 实施期间，Codex先做静态审查；以下是待复现和返修的风险，不是已执行测试结论。

## 首轮重点

- `correct`只对被移除的派生条目设置来源排除，对原始持有者的旧聊天来源没有设置排除。即使当前事实正文已更新，后续组装最近聊天仍可能带入旧内容。需覆盖原始持有者和独立持有者的旧来源；新纠正来源不能同时被误禁。
- `memory_entries.derived_from_entry_id`使用`ON DELETE SET NULL`。A仅自己忘记时，B获分享条目的派生标记可能丢失；后续纠正把它误认为原始事实，默认删除判断也可能改变。派生身份与原始正文的保留必须独立，删除正文不能改变事实的来源性质。
- `remember`按角色＋事实键幂等，但同一来源重新提炼成另一事实键没有幂等控制。需明确“一个来源可以产生多个事实”与“重扫不能重复学习”的契约，在来源版本和提炼批次层处理，不用禁止一个来源多事实的简单规则。
- 查询把全部词用AND连接。现有多为短关键词，尚不能代表实际聊天中的检索问题。加入“还记得我平时喝什么咖啡吗”等自然提问和无关修饰，测量真实漏召回；不得只补与答案同义的词表来提升固定集分数。
- 本轮实现者同时设计策略和所谓holdout样例，不能当作严格盲测。后续由Codex另定独立验收数据，现有holdout仅作为开发阶段分组。

调优工具必须记录实际执行时间和数据场景时间，不能把固定构造时钟写成运行时间。生产实现当前约1160行，超过预期500～800行；需要按职责审查必要性，不靠压行达标。

## 证据边界

正式createStore尚未接入；真实聊天、提炼、在途失效和目录权限仍在后续切片。工具评分不替代这些业务验收。

## r2业务复核

开发者已保留四项失败复现并返修。继续发现两项业务边界不应由实现自行限制：

- 用户在B处明确删除或纠正已知的分享记忆，也应能够操作；PRD没有要求必须回原讲述者A操作。保持B的派生身份是为了来源可追溯，不能演变为拒绝用户管理B的记忆。只有“自动再次转发”应被禁止，用户明确指令另有权限。旧测试把派生身份误判风险与禁止纠正/默认删除绑定，需修正这一错误Oracle并保留理由。
- r2宽召回把查询里出现“不/没/无”等词作为结果必须包含的字面过滤。用户问“我是不是不喜欢咖啡？”时，正确记忆可能是喜欢咖啡；“有什么不含糖的饮料”可能对应无糖茶。检索不能把问题措辞当成事实真值。否定必须保留并交给事实理解，但不宜作为通用硬权限门禁；需保留对立候选的来源与正文，避免丢掉唯一正确事实。原工具把相反措辞一律当违规的分类也需纠正；角色隔离、时效和已删除内容仍是硬门禁。

新增“骑车/自行车、放松/散心、我们/一起”与Codex补充样例高度一致，不能据此声称独立泛化已验证。保留词表作为有限候选方案，正式默认的选择仍需更多独立场景与维护成本判断，不追加无界词典。

## 接入前还需核查

`listAllEntries(limit=10000)`被索引重建调用，清空索引后只重建前10000条会静默丢失后续记忆的可检索性。重建需遍历全部有效存储记录（迭代/分页均可），有界的是每批处理量而不是总记录数。用超过10000条的构造数据验证尾部记录重建前后均可检索；不得仅增加固定上限。
