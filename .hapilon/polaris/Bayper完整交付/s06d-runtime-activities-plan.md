# S06d 正式应用中的日常与探索

Codex受托确定，待S06c独立验收、S04d及S04e释放main后派发。只使用已接受PRD的活动/名单/精力/低频规则，不新建第二个自动调度器。目前main的handleCanvasNodeComplete仅在rotationPending时工作，所以活动服务通过并不意味着桌面会启动活动；这个缺口必须由正式调用链补齐。

## 实现边界

Claude负责代码与测试。优先改main的既有心跳、桌面自然节点和生命周期入口，复用automatic-opportunities与S04e的应用级预算/取消链。必要时以一个小活动执行器隔开用途选择；不复制名单、计时、额度或持久活动事实。不要同时让来源分析和本地活动各拥有一个30分钟抽签器。实际写入文件在前序终态后核对，禁止与在途设置修改并行。

一次合法机会只选择一种可执行用途。已有自动来源分析、本地日常、探索共用机会；选定用途跳过或失败不立即改选另一项，不增加API尝试。无API预算时仍可以选择合资格纯本地日常；这是预先选择用途，不是失败后fallback。公平轮转只需最小持久游标，不引入插件框架。未具备故事/线索制作链时不伪造产出；完整内容链仍为后续必交需求。

## 桌面与生命周期

- 发起活动只建立scheduled，不提前扣精力；桌面真正自然节点回调再调用正式completeNaturalNode。不能因rotationPending为false吞掉活动节点，也不能把心跳本身当作动画完成证明。
- 当前角色开始探索时，与新同屏者切换保持一致；只显示一位，旧角色在小窝/列表显示探索进度。探索进度靠时间推进，不靠屏外动画或模型轮询。候选正式动画不足时明确资源缺口，不用单图平移冒充完成。
- daily持续时长与播放节点都满足后再退出。活动状态由服务快照派生，通知短反应不改变活动ID、有效时间或数值，不打断必需通知。
- 用户聊天/手动换人优先，调用已有暂停入口；结束后按资格恢复同ID，不重复付费。暂停、锁屏、退出后的任务不补做离线时间；恢复仅处理已有进度，新自动机会至少30分钟后。
- 无可用画布或资产错误时，不能默默开始不可见daily并扣费；待开始的daily取消/跳过。已有运行活动的可见故障暂停并保留事实。探索的出发与换人须有可审查的降级表现，不能留两个角色或黑窗口。
- 待交接、聊天、系统暂停等原因合并控制同一个自动入口，任一原因未解除不能resume。关闭顺序先取消活动执行/请求、停止timer和节点监听，再关库，迟到回调不得写入。
