# S03 对话与独属记忆设计

Codex受托决定，2026-10-25；2026-10-27 受托修订事实身份模型。依据PRD、memory-and-sharing.md及本目录memory-source-review.md。分S03a本地记忆业务与检索对照、S03b真实模型聊天与在途失效；权限目录分析在S04接入同一记忆入口。本次修订理由与引用见[s03l-source-identity-plan.md](s03l-source-identity-plan.md)；旧说法由 Git 追溯，本文件只保留当前规则，不并排两套现行规则。

## 数据职责

角色固定内容不由模型随意改写。聊天历史保存实际角色、用户/助手与时间；只有归属角色能组装自身上下文。记忆是有来源的独立事实或经历，不等于聊天全文。重要长期内容与普通细节分开；暂时偏好可有到期时间，到期不覆盖长期偏好，普通内容降低提及优先而非删除重要经历。

所有正式数据使用现有SQLite连接。最低必要结构：记忆记录（稳定ID、角色持有者、kind、正文、来源、可信性质、重要性、有效版本/期限）；来源引用；派生/共享关系；无正文的删除控制；每角色上下文版本。不要另建泛用图数据库或文档事件框架。具体表拆分由Claude按事务边界落地，需审查。

factKey 是角色内的定位提示，不是跨角色事实身份；正文相同不证明主体或事实同一。不同来源保留独立身份；只有显式派生或经核实的关联（associateFacts 前置核验）才能传播纠正、删除、独属、禁分享与共享。真实语义核验尚未闭合，未核验的相似表达保持独立并在歧义时澄清。事实纠正只改变当前理解，真正发生的历史经历可保留；含该偏好推断的摘要必须失效。

## 查询与上下文

读取入口必须给稳定角色ID，不能以昵称查询全部角色。先筛有效持有记录、时效及防回流控制，再做检索。核心设定、有限重要偏好、相关经历和最近对话分段组装，有明确条数/字符预算；不要将所有历史塞进prompt。

第一批实现SQLite FTS5/BM25，中文基线与改进见memory-source-review.md。候选取样、归一化/分词、topK、字符预算集中参数化，结果带命中理由供工具审查。同义检索只影响召回，不自行判定否定、偏好变化或分享许可。

## 写入、分享、纠正和删除

- 提炼只从实际用户输入、真实共同经历或获准来源获取依据；助手自述不是用户偏好。写入带来源ID和来源版本，重复来源幂等；外部分析仅初步理解。
- 明确分享产生指定接收者的新持有记录，保留原讲述者及派生链；默认私聊不自动共享，自动轻量主题分享在S06加入频率门禁。分享不是把所有人的聊天送给同一个模型请求。
- 已定位纠正：单个事务找相同事实的已有持有者和派生记录，停用错误理解、更新必要偏好、失效派生/索引、递增受影响角色上下文版本，再返回成功。未知角色不新增该事实。不依赖模型服务可用。
- 已定位删除：删除可用正文与关联派生正文/FTS内容，清理当前可控展示；仅保存来源引用哈希、定位键摘要及范围等最小控制。不能在审计表保留原文。删除记忆不擅自删除原聊天文件，但后续上下文不能重放其中被删除片段；与该来源有关的旧消息需排除或脱敏。
- 仅A忘记、只让A记得、停止分享均作为明确范围，不默认全员清空。对已核实同一身份的独立来源，纠正覆盖已知持有者；未核实同义表达不凭相似分数扩大删除。
- 重新学习必须有新的用户明确许可/当前表达；旧来源重扫不是许可。以来源与事实控制共同防回流；无法定位同义事实时保留待澄清，不宣称任意改写都能识别。

## 真实聊天与在途结果

用户发送后持久化这一角色的真实输入，使用安全存储中的模型配置调用兼容chat/completions；界面展示等待、取消、失败与重试，不使用假回复。Key不进入renderer或日志。服务提供角色人格、有效记忆和最近历史。回答与可选记忆建议尽量一次请求完成，结构异常可保留有效回答但不写未经验证的记忆。

每个模型请求捕获相关角色记忆版本、来源版本和操作ID。发布回复、写记忆、发气泡前复查；若期间纠正/删除/撤权，取消或丢弃旧结果，不把旧句子先显示再悄悄删。失败不能冒充已记住，用户本地明确删除仍可完成。明确用户聊天与自动活动预算分离，自动请求仍由S06统一调度。
