# S06j 故事回看与相遇窗口：待派发规格

2026-10-27，Codex受托决定。依据PRD的REQ-46/52/53/54/59、clues-and-discovery.md及S06i真实活动接线。当前仅冻结下一最小切片；S03f、S07c仍在途，不并发抢占GUI，也不将本规格记为实现。

## 用户结果与边界

用户能在正式管理窗回看已发生的版本故事，并处理同一份相遇邀请：接纳、稍后、不接纳，以及主动重新开启。采用既有原生布局，在角色页提供局部详情，保持单屏主体、长故事局部滚动。不新增任务中心、收集进度条、积分或催办。

复用story-progress、discovery-outcomes和真实SQLite。首次加载不生成事实；故事内容只来自已记录作者节点，不能把全部作者目录当作用户已经历故事。尚未发布素材继续不可邀请；不得为了演示修改正式assetAvailable。正式发布与自动气泡、服装穿用安排后续切片，本轮仅手动进入管理窗的用户可达路径。

## 接口与实现约束

- main/preload提供最小只读列表/详情及既有邀请操作；全部核对实际管理窗sender，不信任renderer传入角色资料、成熟条件或时间。窗口展示数据从服务端持久事实生成。
- 以稳定storyId/invitationId操作，同一邀请重复点击、重启仍是同一对象。接纳不偷偷改当前角色、固定位置或当日名单；通过现有关系与初始数值服务落库。
- 实际可见邀请才调用acknowledgeInvitation，不能在快照、页面预取、隐藏窗口或后台计时中消耗7天额度。当前领域ACK与自动气泡额度的关系须在派发前再次核对；手动回看已展示邀请不重新消耗。
- 稍后保持安静；不接纳可主动重开，不自动转下一位。处理后刷新相关角色列表与详情；迟到响应不能覆盖已切换页面或角色。素材下架时说明暂不可用，保留故事与邀请身份。
- 允许app/main.cjs、preload、renderer角色页相关文件、一个职责明确的故事展示模块及专属验收；仅在实际接口不足时小改discovery-outcomes，先列明理由。禁止改chat/memory/desktop输入、预算、正式内容发布或版本。生产新增约250～400行是审查信号，超出先拆，禁止通用任务/工作流框架。
- GUI独占后才能派发并实测；代码由Claude Code实施，Codex独立验收。与S07c代码集成后先核对main/desktop边界，不全量覆盖文件。

## Acceptance Contract

共同边界：真实Electron管理窗→preload/IPC→正式服务→真实SQLite；构造作者目录/已发生活动用于可达性夹具，时间可控制，模型不调用。正式未发布目录另测，不把fixture发布等同正式内容可用。

| ID | Given / When | Expected及独立Oracle |
|---|---|---|
| POL-STORYUI-001 | 首次用户没有线索，打开故事区域；之后构造真实活动消费形成首节点并重开 | 空态不泄露未经历节点；已发生内容显示正确讲述者、故事与来源；SQLite事实数、额度与活动数不因查看增加 |
| POL-STORYUI-002 | 成熟、素材可用的同一角色故事，打开邀请并接纳 | 展示后才有首次ACK；重复操作/重启仅一个关系与初始数值，名单/当前角色不变；界面和数据库双侧一致 |
| POL-STORYUI-003 | 同一邀请先稍后、重启回看，再不接纳、主动重开 | 身份和背景连续，稍后不催促，拒绝不自动替换下一位；主动重开不刷新首次展示时间，无惩罚数值变化 |
| POL-STORYUI-004 | 邀请准备后窗口隐藏/切页，或展示前素材不可用；恢复页面 | 隐藏无ACK，素材不可用不得接纳/换目标；恢复后正确展示一次，失效页面回执不消费额度 |
| POL-STORYUI-005 | 快速切换详情与迟到响应，接纳写失败或重复点击 | 不显示其他目标旧结果；事务失败不产生半个关系或成功提示，可有界重试；原始失败证据保留 |

每条Case记录PASS/FAIL/ERROR/INCONCLUSIVE/NOT_COVERED及截图/SQLite观测，额外核对实际100%管理窗尺寸、主要内容单屏和无抢焦点。测试夹具只在专用目录；确认父子进程退出后清理，不能删除仍使用中的数据库。
