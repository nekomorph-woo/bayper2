# S03h 明确“只让你记得”：实施规格

2026-10-27，Codex受托决定。依据memory-and-sharing.md的用户控制表与同步生效规则，接续S03f/S03g。仅解决已定位同一factKey及现有派生链的独属保留；不同factKey语义归并继续独立研究，不能据此声称全库语义控制已完成。

## 用户结果与边界

当前角色已持有某条事实，用户明确要求“这件事只让你记得”时，保留她的有效记忆，清除其他已有持有者对应可用正文及派生理解，禁止再次传播。未知角色不因操作获得信息；没有额外API唤醒其他角色，没有惩罚、名单/衣装/故事进度变化。角色原本只是听说也可以成为唯一保留者，仍保留来源语义，不改成亲历。

已定位事实可通过本地记忆面板执行，不依赖模型连通；聊天入口沿用本轮真实用户命令+有限候选M映射，模型仅建议。歧义澄清，引用、假设、否定及单纯功能询问不执行。对“只让A忘记”与“之后别分享”的既有行为保持区别，不把它们改为独属保留。

## 实现切片

先服务与事务，再聊天和面板；每片由Claude Code实现、Codex独立验收。优先复用memory-store控制表、版本与删除方法，不另建身份/权限框架。新增必要操作可命名keepExclusive，命名最终由职责清晰度决定。

- 选中entryId和expectedVersion确认当前持有；全程同一SQLite事务，保留者不删，其他已持有者删正文并记录无正文防回流控制；添加事实禁止分享。保留者若是派生记录，删除原持有者也不破坏其有效内容及可说明来源。
- 其他持有者版本必须失效；保留者权限改变也应使旧操作上下文失效，以免在途转告继续提交。最终本地确认与操作同事务；取消、来源变更和落库失败不能半完成。
- 既有禁分享生效于share/relay；历史来源重分析不能重建被清除的持有关系。明确新授权的解除/重新记住沿已有语义，不借此自动解除其他角色自忘限制。
- 不保存删除正文到审计表，不改用户聊天原文；UI明确范围且只确认一次。
- 服务首片允许app/memory.cjs及必要memory-store，专属tests/acceptance/memory-exclusive.spec.cjs。约100～180生产行为规模信号，测试用清楚固定场景，不搭框架。后续聊天/面板范围另派，不一次扩展所有入口。

## Acceptance Contract（服务首片）

真实memory入口、SQLite与正式检索/relay，不mock核心；构造角色和事实，控制时间，独立核对持有/正文/版本/检索/禁止副作用。

| ID | Given / When | Expected / Oracle |
|---|---|---|
| POL-EXCLUSIVE-001 | A持有事实，B为转告副本，C未知；A选中保留独属 | A仍有效；B正文/检索清除，C无新增；A/B版本变化，角色数值/名单/内容进度不变 |
| POL-EXCLUSIVE-002 | D原来源→A听说→B派生；A保留独属 | D/B可用正文清除，A保留听D说过的来源，不能变亲历；后续share/relay拒绝 |
| POL-EXCLUSIVE-003 | 重复调用、过期版本、未知条目/非持有者 | 幂等或明确拒绝，无额外副作用、无假成功；有效A内容不丢 |
| POL-EXCLUSIVE-004 | 删除中途或最后版本写失败 | 全事务回滚，持有、正文、控制及版本一致，重试可成功 |
| POL-EXCLUSIVE-005 | 清除后旧来源重新记忆/历史派生转告，及无关事实 | 对应事实不回流；无关事实和控制保持，不清整段历史 |

后续聊天/GUI需另验证实际输入或选中按钮、单次确认、在途结果失效与重启持久；服务PASS不替代这些边界。
