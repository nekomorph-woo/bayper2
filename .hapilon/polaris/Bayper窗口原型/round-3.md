# 第三轮：实际数据与交互一致性返修

等待第二轮结束并完成实际截图后下发；本文件是Codex审查意见，不能把待检查项记成通过。仅当前OpenDesign项目代码，仍由Claude Code实现，不改仓库/Git/真实系统。

## 数据与现行PRD一致

- 角色记忆是她对用户与共同经历的了解。第二轮data.js把大量“偏好”写成角色自己的喝茶/外套/毯子习惯，且来源“凛说过”，这与“她记得关于你的事”混淆。角色自身习惯保留概览；记忆偏好改为用户明确表达，例如“你更喜欢温茶”“你不希望工作中被频繁打断”，来源“你告诉凛”。自动转述仅轻量共同见闻，不把用户睡眠/早餐等个人偏好写成默认跨角色分享。
- 设置→来源隐私应发现Coding Agent并请求其会话目录，不是给“工作笔记/下载”泛目录分析授权。演示Claude Code与Codex两类来源，目录采用明确模拟标签，不读真实目录。开关与授权分离，默认不分析；撤销不删除既有记忆。
- “纠正”同步已持有同一理解的角色；“删除”默认所有已持有者，可明确改为仅当前角色。记忆与共享PRD是唯一依据，round-2措辞如有歧义以本条为准。不要把修改广播给未知者。至少一项共享偏好构造样本由用户明确转告，用于验证纠正关联；独立角色记录不受影响。
- 通知与当前状态应有可解释的顺序：写周报16:40需要处理却当前工作中时，必须有之后继续工作记录；备份脚本显示16:12结束而历史13:50结束，统一一次任务时间，或明确不同运行，不无证据冲突。
- 服装故事避免“读完就能换”的虚假承诺；当前无第二服装资产时保持清楚未解锁状态，故事阅读并非自动解锁按钮。
- 陪伴预算按PRD：每30分钟评估，合资格25%机会；全应用滚动1小时1次、8小时4次、24小时6次，并发1；探索4小时1次/24小时2次。用简短自然摘要和按需展开说明即可，不形成上下午任务排班，不显示“应完成”的任务。
- 原型版本文案写“交互原型 · 2026.10”，不要硬编码0.1.0冒充仓库实际版本。名称、用户和事件全部模拟。

## 必须修复的角色归属错误

已读第二轮home.js：hero依赖fixedId，今日名单使用acceptedIds，设固定位直接改桌面。这与PRD三层不同概念冲突，不能交付：
- 最小模拟状态分开 acceptedIds（已接纳）、dailyIds（默认rin/hu/cheng）、fixedId（rin）、desktopId（rin）。无需做真实每日调度引擎。
- 首页“今日陪伴”只显示dailyIds；绫接纳后仅进角色册/小窝集合，dailyIds、fixedId、desktopId均保持不变。
- 更换固定位与“请她陪我”分别操作，设固定位不强行换桌面/中断探索。桌面主图/聊天归属desktopId，不能永远等于fixedId。
- “请她陪我”支持名单内随机成员与名单外临时陪伴，明确临时不改当日名单。探索中的成员先确认暂停探索再切换。原在屏成员回小窝，始终只有一个desktop状态。
- 已接纳绫还无图不要写“来到小窝之后才画”暗示动态生图；显示低调文字占位“原型暂未提供角色图”，正式角色随版本提供。聊天可用她自己的固定演示回应，不串其他角色。
- 名单/角色详情用昵称一致显示，避免编辑后主图标题改了但副标题仍旧。
- 概览补简洁关系状态（亲密、精力、心情对应“渐渐熟悉 / 精力充足 / 心情平静”等自然标签，详情可显示构造数值），不是任务进度或刷数值奖励。
- 故事日期排序，删除首页说明“不会有进度条”这种设计解释，改自然内容摘要。连接页删除“每秒从本机读取一次”等虚构运行机制，来源技术ID非必要不摆正文。
