# 切片与场景范围

## 输入

读取已确认的需求材料与全局业务模型，以及当前模式的现状、影响或场景清单。缺少影响范围选择的产品决定时，先回到 [需求与 PRD](prd.md) 讨论。

## 从零与增量开发

按用户价值和完整业务路径提出可逐步交付的垂直切片，不按前端、后端、数据库、框架或基础设施拆分。

每个切片让用户完成一件有意义的事，尽量小但不能切断完整业务路径。可以采用简单实现、固定数据或 Mock，但明确其限制及不能证明的能力。

模块、协议、数据迁移或诊断探针可以是切片内的实施批次，但必须指向父级用户结果，注明还缺哪段真实路径。不得每完成一个内部能力就把它改称已交付切片。连续多个技术批次仍无业务闭环时，回到父级范围与依赖审查，决定集成、修复真实阻塞或调整路线，并记录依据。

每个候选切片只说明：名称与用户价值、起点到结果的业务路径、范围及排除项、可观察的验收目标、依赖与推荐顺序。

核对是否遗漏 PRD 的重要目标；暂不纳入的目标列为后续事项，而非悄悄删除。按依赖、复杂度与验证价值推荐顺序，不追求平均大小，不提前建设未来切片的通用能力。指出过大、缺少独立价值或仍有关键决策的候选。

增量开发还需说明每个切片影响的旧行为、兼容要求及回归范围。简单改动可省略单独切片规划，但在状态中保留本轮范围及理由。

## 补建验收

把切片规划替换为业务场景范围选择。按能力、用户路径和风险分组，列出当前支持的行为、依据、重要边界与未知项。

先选择一个能调查清楚、值得长期保护的场景集，不一次扫描全仓并生成几百条 Case。不将当前代码的所有行为直接纳入正式验收。

## 产出与确认

输出候选切片或场景组及推荐顺序，可按需保存 `slices.md` 或 `scenario-inventory.md`。由用户选择本轮范围；已有明确选择直接复用。

完成条件：本轮范围、价值、验收目标和排除项已确认。此时只完成范围规划，不展开详细业务模型、完整 Case、技术架构或测试代码。
